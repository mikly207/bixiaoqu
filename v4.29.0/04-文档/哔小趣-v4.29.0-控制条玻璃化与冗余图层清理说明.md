## 二、为什么以前看起来是「全黑横带」

你截图里那一条不黑是错觉，实测像素是这样的（1080×646 截图，控制条内部 x=300,y=62）：

```
页面底色 #16181D  →  实测 (22, 23, 28)
控制条内部        →  实测 (15, 15, 18)     ← 比页面底色还暗一档
```

原因很直接：**控制条在页面流里自占一行，背后是页面底色**。
`GlassPanel` 的压暗层是 29% 黑，叠在已经接近黑的 `#16181D` 上，
结果就是「比黑再黑一点点」的一块 —— 玻璃背后什么都没有，透出来的还是同一块黑。

于是前几版做的所有光学工作（端面明暗、折射线、单道描边、扫光）
全部被浪费掉了：**没有可透的东西，玻璃就只是一块带圆角的深色板**。

> 玻璃不是一种颜色，是「背后有东西」这件事被看见的方式。

## 三、改法：把控制条压到画面下沿

### 1. 结构上只改了一处：布局参数

```java
// v4.28.0：控制条自占一行
lp.leftMargin = dp(10); lp.rightMargin = dp(10); lp.bottomMargin = dp(8);
root.addView(ctrlWrap, lp);

// v4.29.0：上移自身高度，压在画面下沿
lp.leftMargin = dp(10); lp.rightMargin = dp(10);
lp.topMargin = -ctrlBarHeight();          // = -57dp
root.addView(ctrlWrap, flowCtrlLp());
```

`topMargin` 取负的自身高度，于是它对纵向排布的**高度贡献为 0**：

- 不再额外占一屏高度（省 57dp 板 + 8dp 边距）；
- 控制条显示 / 隐藏时，下面的简介与推荐**不会上下跳动**
  —— 这是以前不敢做「点画面隐藏控制条」的原因，现在顺手解决了；
- 背后是视频帧，23% 的压暗刚好「白字可读 + 画面透得出来」。

高度是逐项加出来的，不是写死 `dp(57)`：

```java
int ctrlBarHeight() {
    return dp(4) * 2 + dp(28) + dp(1) + dp(16) + dp(4);
    //     板上下padding   一行按钮   板下缝   进度槽   槽下留白
}
```

任何 density 下这串值都等于那几个 View 的真实高度之和，不会因为四舍五入多出 1~2 像素的缝。

### 2. 全屏 / 分屏 / 竖屏铺满 的来回切换

`ctrlToRootFlow()` 现在也用同一份 `flowCtrlLp()`，并在归位时把浓度同步降到 23%：

```java
ctrlTint(0x3C);   // 回到页面流 = 背后是画面，压到 23% 才透
```

否则从全屏退回详情页时，会带回一块 27% 的深色板 —— 玻璃又变回塑料。
全屏 / 横屏分屏本身仍然走 `ctrlToOverlay()`（浮在画面上），那套逻辑没动。

### 3. 删掉「简介 / 评论 50」

那两行字不是一个页签：**点不动、也不切页**，只是把紧跟着的 UP 主行
和下面的统计行再复述一遍，却固定吃掉 26dp（6+2 内边距 + 18 文字高）。
评论数在下面的 `3509播放 · 50评论 · 2弹幕` 里已经有了。

```java
// 删除：tabRow / tabIntro / tabComment 全套（含 applyMeta 里的 setText）
// 评论数只走统计行，重复信息只留一处
```

v4.16.1 加它是为了"像 B 站详情页右栏"，但那套页签在**右栏**才有意义；
竖屏详情页是纵向直排，本来就没有"切换"的语义。

## 四、省下来的 91dp 去哪了

```
旧：视频 230 + 控制条整行 65 + 简介/评论 26 = 321dp
新：视频 230（控制条压在画面内）      = 230dp
                                    ─────────
                                     省 91dp
```

91dp 在一部 640~740dp 高的手机上约等于**一屏推荐位**（2~3 条），
而且视频画面本身的尺寸一点没变（还是 230dp 高、按宽高比居中）。

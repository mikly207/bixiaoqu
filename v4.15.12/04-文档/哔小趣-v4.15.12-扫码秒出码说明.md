# 哔小趣 v4.15.12 —— 扫码登录：一步到位出码

**版本**：v4.15.12（versionCode 108）
**兼容**：Android 5.1（API 22）及以上
**签名**：证书不变（SHA-256 前缀 `0930aba7…`），可直接覆盖安装

---

## 一、你截图里的 42 秒卡住，根因只有一句

旧版（v4.15.11）的生成顺序是 **先直连 B 站 → 直连不通才走云端**。
而你手机上「本机 → passport.bilibili.com」这条链路本身是挂起的：连接不返回、也不报错，只能干等到超时。
两条线路 × 2 次重试，最坏 50 秒以上 —— 截图停在「正在连接 B 站…（42s）」就是这么来的。
云端兜底排在最后，永远轮不到。

**实测数据**（刚刚在服务端跑的真实请求）：

| 通道 | 生成耗时 | 结果 |
| --- | --- | --- |
| 服务器 → passport.bilibili.com | **0.07 秒** | code=0，返回 qrcode_key |
| 你手机 → passport.bilibili.com | 40 秒以上无响应 | 超时（DNS/网关/TLS 环节被卡） |
| App → 云端接口 | **0.48 秒** | code=0，返回 qrcode_key |

也就是说：**码本身 0.5 秒就能拿到，只是旧版把慢的那条路排在了前面。**

## 二、这次的改动（只有一处关键，但是决定性的）

| 改动 | 说明 |
| --- | --- |
| **生成顺序反转：云端优先** | `qrcodeGenerate()` 第一步就打云端接口，**约 1 秒出码**；云端不通才回退直连 |
| **直连降级为备份** | 超时 4s/5s，只用于云端万一不可达，不再让用户对着转圈等 |
| **云端超时收紧** | 6s/8s。8 秒不回即判定本机到云端也不通，立刻换直连，不在一条死路上耗 |
| **文案改实话** | 「正在获取二维码…（Ns）／云端通道约 1 秒，稍等」；出码后「请用 B 站 App 扫码，3 分钟内有效」 |
| **失败即转网页登录** | 两条通道全废时自动跳 WebView 登录，保证一定登得上 |

登录环节（v4.15.11 已修，本版沿用，无需再动）：
- 凭据按 `Set-Cookie` 原值 → URL 原样（`%2C` 不解码）→ 解码 三级取值；
- 整套 Cookie 入库（`SESSDATA / bili_jct / DedeUserID / DedeUserID__ckMd5 / sid`），`full_cookie` 持久化；
- 确认后调 `nav` 读 **`data.isLogin`**（B 站把登录态放在 data 节点内，读顶层永远是 undefined），延迟生效最多重试 4 次；
- `addCookie` 按 `;` 分段解析，不再只按首个 `=` 切分。

> 云端接口刚复测：`qr_gen` → `code=0` + key；`qr_poll` → `data.code=86101`（未扫码），状态机正常。

## 三、验证步骤

1. 覆盖安装 `哔小趣-v4.15.12.apk`；
2. `我的 → 登录 → 二维码登录`；
3. **1 秒左右出码**（最多 3 秒），不再出现「连接 B 站…（42s）」；
4. 手机 B 站 App 扫码 → 手机上点「确认登录」；
5. App 提示「登录成功 ✓ 昵称」并自动返回，头像昵称同步。

如果出码后扫码提示过期：点「刷新二维码」即可（二维码本身 180 秒有效，过期会自动换一张）。

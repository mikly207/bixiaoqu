# 哔小趣 v4.41.0 直播实验版 · 卡死修复 + 实时弹幕 + 演示模式

> 针对「点进直播间几秒就卡死、退出再进也恢复不了」的恶性 bug 彻底修复，
> 同时接入真实弹幕、优化线路，并提供内置演示片源兜底。手机/平板双版本同步。

---

## 一、卡死根因（已定位并修复）

旧版 v4.40 卡死是四个问题叠加：

| 根因 | 后果 | v4.41 修复 |
|---|---|---|
| 代理线程池仅 6 个，且 socket 无超时 | m3u8 反复刷新 + 并发分片把 6 个线程占满 → 全部请求排队卡死 | 线程池扩到 20 + 有界队列 + 过载丢弃；每个 socket 设 9s 超时 |
| 退出再进时旧请求还在跑 | 旧请求把线程池彻底堵死 →「退出再进恢复不了」 | **代际隔离**：每次播放 `newGeneration()` 强制关闭所有旧连接，旧请求直接返回 410 |
| 慢 CDN 的 read 无熔断 | 单个慢请求挂住就拖垮整池 | 分片转发加 25s 总时长熔断 + 客户端断连检测，立即释放 |
| 播放器 onError 无条件无限重连 | 失败时疯狂重建解码器/线程，越卡越死 | 有限重连（最多 3 次，递增延迟），超限给明确出路 |

额外修复：accept 线程改为守护线程，避免线程泄漏。

## 二、实时弹幕（本次新增）

- 新增 `LiveDanmakuClient`：**纯 Java 实现 B站直播弹幕 WebSocket 协议**，无第三方依赖。
  - WSS 握手 `broadcastlv.chat.bilibili.com/sub`
  - 二进制帧认证（op=7）、15s 心跳（op=2）、解析推送包中的 `DANMU_MSG`（op=5）
  - 独立守护线程 + 指数退避重连（1s→15s），回调切回主线程驱动弹幕层
  - Activity 退出时 `stop()` 彻底释放
- 弹幕开关从「关」切到「开」会补连；不再只是本地氛围弹幕。
- 说明：沙箱环境无法直连弹幕服务器（网络限制），协议按 B站公开标准实现，真机可用；连接失败时自动降级，不影响播放。

## 三、线路优化（本次新增）

- `livePlayUrls` 取回 playUrl 返回的**全部 m3u8 线路**（实测同房间有 2 条 CDN），不再只用第一条。
- 代理侧**多线路择优**：逐条探测，第一条可用即用；胜出的 CDN host 记入**线路亲和表**，后续分片都走同一条好线路，避免来回抖动。
- m3u8 加 **900ms 短缓存**，抵消 VideoView 的重复刷新请求。
- 分片请求支持 Range、首包即达，单线路卡顿时可快速切换。

## 四、演示模式兜底（本次新增）

- 把你提供的视频内置为 `res/raw/live_demo.mp4`（竖屏 640×1408、8.7s、h264/aac）。
- 直播页右上角有「**演示**」按钮：一键用内置片源在 App 内稳定播放，配氛围弹幕。
- 当直播取流失败 / 多次中断 / 风控时，界面会明确提示「可点演示观看」，保证任何情况下都有可看内容。
- 动态查找资源 id，不依赖编译期 R 字段，兼容项目的纯 javac 构建链。

## 一、修复：四大名著翻页切章卡在「正在载入」

### 问题复现
截图里标题已经是「第三回（3/100）」，正文却一直停在「正在载入第 1 回…」，点击下一章/目录都无法加载。

### 根因
v4.57 重写阅读器时引入了一个**竞态死锁**：

```java
// 旧代码：curChapter 只在异步回调里才更新
Thread th = new Thread(() -> {
    Chapter ch = BookStore.chapter(...);
    ui.post(() -> {
        if (curChapter != target) return;   // ← 这里的 curChapter 还是旧章号
        curChapter = target;                 // ← 所以永远走不到这一行
        ...
    });
});
```

`loadChapter()` 发出请求时没有立即更新 `curChapter`，而回调又用 `curChapter != target` 判断「是否已翻走」。结果是**每一次切章都被自己的回调丢弃**——正文永远停在占位文字，标题与正文脱节。首次进入之所以正常，是因为 `onCreate` 预先把 `curChapter` 设成了恢复的章号，恰好等于 target。

### 修复内容
1. **发出请求时立即同步状态**：`curChapter = target`、标题即时刷新，不再等异步回调。
2. **改用单调递增的 `loadToken` 判过期**：只有最新一次请求的回调可以落地，快速连点目录/上一章/下一章不会串章。
3. **删除分段渲染**：旧版每 1500 字 `sleep(12ms)`，四万字要 300ms+，还多起一个线程。现在一次性 `setText`，实测更快且无竞态。
4. **后台预热**：进入阅读器时另起线程提前 gzip 解压整本书；`rawOf()` 整段加锁，预热与加载并发时只解压一次，避免重复分配 2~3MB 数组。
5. **防止误翻章**：换章、改字号期间内容高度会突变，短暂屏蔽「滑到底自动翻章」，等布局稳定两帧后再恢复。

保留：字号/护眼/章节与章内位置持久化、目录 ListView 复用、后台预取下一章、进度条与字数反馈。

## 三、游戏厅 / 留声机 / 音乐吧：捐赠解锁

### 说明
源码中并没有独立叫「音乐吧」的入口，音乐相关内容都在「留声机」里；「小说吧」是阅读入口。为避免误解，本版对「我的」页三个娱乐入口统一加了门禁：

- **游戏厅** → 捐赠解锁
- **留声机** → 捐赠解锁
- **小说吧 · 音乐吧** → 捐赠解锁

### 实现方式
- 入口统一走 `MainActivity.openGated()`，判定复用 `DonateApi.isUnlocked(this)` —— 与登录门禁**完全同源**，都是服务端 RSA 签名且未过期的凭证。
- **已捐赠用户零感知**：点开直接进入，行为和旧版一致。
- 未解锁用户弹引导页：「去捐赠解锁」跳转捐赠页（最低 1 元）；已付款拿到激活码的用户可在捐赠页粘贴兑换。
- 在 `GameActivity` / `MusicActivity` / `NovelActivity` 的 `onCreate` 又各加了一层自检，从任意入口（含外部跳转）进入都必须已解锁。
- 手机端 `MainActivity` 有平台适配分支，本次采用精确替换同步，**未破坏手机版窄屏/双列布局**。

> 安全说明：本版**没有**引入任何本地「点一下就解锁」的分支。客户端仍只认验签通过的凭证，改本地缓存无法伪造捐赠身份。

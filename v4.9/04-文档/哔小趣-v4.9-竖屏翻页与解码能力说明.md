# 哔小趣 v4.9 更新说明

本轮共完成 4 项需求，外加一轮底层重构。APK 545 KB（与 v4.8 基本持平）。

---

## 一、竖屏上下滑翻视频（抖音式）

竖屏视频铺满整屏后，**上滑看下一个、下滑看上一个**，跟手拖动、松手吸附，体验对齐抖音。

### 为什么必须换掉画面承载

旧版用系统 `VideoView`，它内部是 **SurfaceView** —— 位于独立图层，父容器做位移时画面根本不跟随，
所以「拖动画面」这种效果在旧架构下无法实现。

本轮新写 `TxVideoView`（`TextureView` + `MediaPlayer`）替换，画面画在普通 View 层级里，可以自由做位移/淡入淡出。
附带收益：`setDataSource` 的网络建连挪到子线程，主线程不再被 CDN 握手阻塞。

### 翻页是怎么做的

```
holder
 ├ bgCover      背景封面
 ├ swipeLayer   翻页容器（永远 VISIBLE，它是画面槽的父容器）
 │   ├ slotCur  当前槽：画面 + 弹幕（随手指位移）
 │   ├ slotNext 下一槽：封面 + 标题（从下方顶上来）
 │   └ slotPrev 上一槽：封面 + 标题（从上方压下来）
 └ overlay      控制层（触摸入口，永远最上）
```

- 上滑：`slotCur.translationY = dy`，`slotNext.translationY = dy + 屏高` → 下一槽从屏幕下方跟进
- 下滑：`slotPrev.translationY = dy - 屏高` → 上一槽从屏幕上方跟进
- 切到相邻槽后，它停在屏幕中央当**海报**（封面图），等新视频**真正渲染出第一帧**再淡出 —— 全程不黑屏

分成上下两个槽而不是共用一个，是为了避免「上滑到一半改下滑」时封面跳到另一边闪烁。

### 滑动队列从哪来

实测两个接口的竖屏密度差别很大：

| 数据源 | 竖屏占比 |
|---|---|
| `related`（当前视频的相似推荐） | **80%**（32/40，从竖屏视频出发时） |
| `popular`（热门榜单） | 16% |

所以**以 related 为主力、popular 只作补充**，队列优先收竖屏视频。
滑到队列末尾会自动续拉一批新条目，保证「一直能滑下去」。

## 二、滑动调度优化（不卡顿的关键）

### 1. 播放地址预取缓存（`BiliApi`）

新增进程内 LRU 缓存（16 条 / 30 分钟 TTL），键为 `bvid + cid + 清晰度档位`。

- 滑动时提前在后台线程算好**下一条 / 再下一条 / 上一条**的 playurl
- 松手切换的瞬间直接命中缓存 → **零网络等待**
- 加了「在途去重」集合，防止快速连滑时对同一个视频重复起线程重复打接口（会加剧 B 站风控）

### 2. 封面预取

新增 `ImgLoader.prefetch()`，把封面下载后**写进内存 LRU**（原来的 `fetch` 只落磁盘，滑到时仍要等网络）。
内存缓存从 8MB 提到 **16MB** —— 一张全宽竖屏封面解码后约 4~5MB，8MB 只装得下 1~2 张，
预取的封面会互相逐出，等于白预取。

### 3. 元数据前置

队列条目自带 标题 / cid / 宽高比 / 时长，翻页时**直接填界面**，不等 `loadVideoMeta` 的网络往返。
画面一出来，标题、UP主、进度条时长就已经是对的。

### 4. 去掉无用请求

翻页时不再重拉「相关推荐」列表（竖屏铺满时它根本不可见，还会跟预取抢带宽）。

### 5. 线程与生命周期

- 新增线程：`bxq-prefetch` / `swipe-feed` / `swipe-more`，全部有明确收尾
- 页面销毁时取消在途翻页动画，避免回调在死页面上新建播放器

## 三、竖屏加载界面：去掉图标，只留文字

竖屏沉浸模式下隐藏吉祥物图标与「Dynamo」署名，**只保留「正在加载喵~」文字**：

- 文字加大加亮（17sp / 纯白），成为唯一视觉焦点
- 底板收紧，去掉图标后原来的大留白会显得很空
- 横屏与普通详情页**保持原有完整样式**不变

## 四、每个视频的解码能力

新增一个「解码」按钮（清晰度按钮旁），点开列出**本视频**的编码清单：

```
本视频解码能力
─────────────────
4K · H.265            ✗ 本机不支持
1080P60 · H.264      ✓ 本机可解
1080P · H.264        ✓ 本机可解
```

判定方式：查系统 `MediaCodecList`，逐条比对 B 站返回的 DASH 轨道编码族。

**这个功能解决的实际困惑**：同一支视频 B 站会同时给 AVC / HEVC / AV1 多条轨。
用户把清晰度拉到 4K 却只拿到 1080P —— 往往不是网络问题，而是「4K 只有 AV1 轨，而本机解码器不支持 AV1」。
以前这是个黑箱（用户只会觉得软件有 bug），现在把机器的能力上限直接摊开。

## 五、顺手修掉的隐患

三轮独立代码审查，共发现并修复 **16 个真实缺陷**，其中 2 个是致命回归：

| 严重度 | 问题 | 后果 |
|---|---|---|
| 致命 | 相邻槽是黑色不透明底且初始可见 | 普通详情页（横屏视频）画面被黑块盖死 |
| 致命 | 退出竖屏铺满时把整个翻页容器设 GONE | 连画面槽一起隐藏 →「退出铺满后画面空白」 |
| 严重 | 退出竖屏时未取消在途翻页动画 | 动画回调把已隐藏的槽重新设为可见 → 黑屏复活 |
| 严重 | 海报在 `onPrepared` 就淡出 | `onPrepared` 只代表「流就绪」，画面还没出帧 → 露出上一支视频的残帧 |
| 严重 | 翻页后 `swipeDy` 停在 ±屏高 | 下一次抬手拿旧值比阈值 → 白翻一页 |
| 中 | `ACTION_CANCEL` 当成抬手确认 | 手势被系统打断也会真的翻页 |
| 中 | 多指打断翻页后状态残留 | 画面卡在偏移位置，下一次拖动跳变 |
| 中 | 上一槽封面从未预取 | 第一次下滑必见黑底（最长 8 秒） |
| 中 | 翻页时海报未撤（播放失败路径） | 网络失败时封面永久盖屏 |
| 中 | 续播视频用「进度>0」判定首帧 | 续播时进度直接是 seek 目标值 → 海报提前淡出 |
| 轻 | `swipeDy == 0f` 浮点相等 | 死分支，拖回原位不隐藏预览槽 |
| 轻 | 两个槽的淡出相互干扰 | 海报一闪就没 |
| 轻 | `swipeLastY` 跨手势残留 | 动画后第一个 MOVE 算出巨大位移 |
| 轻 | 退出全屏漏恢复翻页层高度 | 画面被顶到屏幕外 |
| 轻 | 预取无在途去重 | 快速连滑重复打接口 |
| 轻 | 封面预取不写内存 LRU | 「零等待命中」不成立 |

首帧判定最终改用 **`TextureView.onSurfaceTextureUpdated` 回调**（真实出帧信号），
比轮询播放进度可靠得多。

## 七、使用说明

1. 直接覆盖安装 v4.8（签名一致，无需卸载）
2. 打开一个**竖屏视频**，等它自动铺满整屏后即可上下滑动翻页
3. 竖屏下**纵向滑动 = 翻页**，**横向滑动 = 亮度/音量**（原纵向调亮度/音量已改为横向，功能不丢）
4. 竖屏加载时只有文字，没有小电视图标了
5. 点控制条上的「解码」按钮，看本视频的编码能力清单

> 提示：滑动翻页依赖竖屏铺满模式。若在设置里关了「竖屏视频横屏优化」，或视频本身是横屏的，
> 则不会进入沉浸模式，也就无从翻页 —— 这是设计如此。

# 哔小趣 v4.14.0 更新说明

> 基于 v4.13.1，versionCode 70，签名与历版一致可直接覆盖安装。
> minSdk 22（Android 5.1）兼容保持不变。

## 关于 ExoPlayer 的说明（先读这段）

你列的这套参数是 **ExoPlayer 专属 API**：`MediaSource`、`DefaultLoadControl.setMinBufferMs`、
`DefaultBandwidthMeter`、`setMediaSource` 等。本工程**并未使用 ExoPlayer**——它是纯 Java、
无 androidx 的手工构建项目，播放链路是「系统 `VideoView`/`MediaPlayer`（画面）+ 独立音轨
`MediaPlayer` + 本地转发代理 `LocalProxy`」。强行引入 ExoPlayer 需要整套 AndroidX 依赖与
Gradle 构建链，APK 会从 627KB 涨到数 MB，且与现有极简架构冲突。

因此本版做的是**等效落地**：在你现有架构上实现同样目标（切换更快、起播更快、掉线更少、
内存更省），而不是把 ExoPlayer 的类名硬塞进来。下面逐条对应。

## 需求 → 等效实现对照

| 你的要求（ExoPlayer 术语） | 本版实现 | 效果 |
|---|---|---|
| 复用同一播放器实例，切视频只换源、不销毁重建 | 音轨 `MediaPlayer` 改为**实例复用**：切流只 `reset()` 换源，不再 `release()+new`；`release()` 只在页面 `onDestroy` 调用。画面 `VideoView` 实例全程不重建 | 省去 MediaPlayer 对象/JNI/音频会话初始化，降低切流开销与 GC |
| 起播仅需缓冲 800ms，减少等待 | socket 开 `TCP_NODELAY`（禁 Nagle）+ 转发缓冲首块立刻下发 + 256KB 转发块 | 首批数据不再滞留，等效缩短起播等待 |
| 缓冲最小 2s / 最大 12s | MediaPlayer 的缓冲窗口由系统管理，无公开 API 直接设定；本版通过代理层的「256KB 稳态转发 + 不堆积」逼近稳态缓冲目标，避免系统缓冲被撑爆或被饿空 | 长时间播放更稳，减少卡顿 |
| 带宽预估初始 10Mbps，快速适配码率 | `BiliApi.estBandwidthBps` 初值 10Mbps，挑流时按「预估×1.4」做同档位码率 Tie-break（不改变你选的画质档位）；代理转发实测吞吐回填估算并指数平滑 | 低带宽不会一上来选到扛不住的超高码率轨，起播更快 |
| 分片并发控制在 2 个 | `LocalProxy.chunkGate` + `BiliApi.PREFETCH_GATE` 双信号量，均为 2 | CDN 带 token 的直链不再因请求堆积而过期的 403/断连 |
| 只预拉索引和首段，避免请求堆积、token 过期 | 竖屏预取保持只拉 playurl 索引 JSON + 封面，**不拉媒体分片**；且受并发闸门限制 | 请求数量可控，token 不过期 |
| 切视频瞬间先暂停旧流、临时隐藏弹幕，就绪后恢复 | 新增 `pauseCurrentForSwitch()`：暂停画面+音轨、`dmView.setSuspended(true)` 隐藏弹幕并清在飞的弹幕；新增 `resumeDanmakuWhenReady()` 在首帧进度推进后（dmTick 检测）自动恢复并对齐进度 | 切流瞬间无旧视频残影/串音/串弹幕 |
| 仅页面彻底关闭才 release | `release()` 收拢到 `onDestroy()` 一处；`fallbackMux`/`startHard`/切流全部改为 `pauseCurrentForSwitch()` | 兼顾切换迅捷与内存释放 |

## 系统固有限制（如实说明）

- **解码器重建**：Android `MediaPlayer` 换源必须走 `reset()`，系统会回收并重建编解码器，
  这一点无法像 ExoPlayer「换 MediaSource 不动解码器」那样彻底省掉。本版省掉的是
  MediaPlayer 对象创建、AudioSession 申请、JNI 初始化这几部分开销。
- **缓冲窗口精确毫秒值**：`DefaultLoadControl` 的 min/max/起播毫秒在 MediaPlayer 上没有
  对应公开接口，本版用代理层转发策略逼近，无法给出精确的「2s/12s/800ms」保证。
- 若确实需要这些精确能力，唯一路径是引入 ExoPlayer（AndroidX + 构建链重写），可另行评估。

# 哔小趣 v4.40.0 直播实验版 · 修复说明

> 本版本核心目标：**直播内嵌**——在 App 内直接看直播，不再跳转第三方浏览器。
> 平板版 / 手机版同步更新，双目标差异（平板横屏分屏、手机全屏）完整保留。

---

## 一、直播内嵌（本次重点）

### 之前的问题
直播频道此前已从顶部频道栏移除；残留的 `loadLive()` 只是 `Intent.ACTION_VIEW` 拉起系统浏览器打开 `live.bilibili.com`——等于跳出 App，体验割裂，且很多设备无浏览器时直接失败。

### 现在的实现

| 环节 | 方案 |
|---|---|
| 入口 | 顶部频道栏恢复「直播」（第一个 tab），点击直接进入内嵌直播页 `LiveActivity` |
| 分区 | 调用 `room/v1/Area/getList`，把一级/二级分区铺成横滑标签 |
| 房间列表 | 调用 `room/v3/area/getRoomList`，两列网格展示封面/标题/主播/人气，滚动自动加载下一页 |
| 流地址 | 调用 `room/v1/Room/playUrl?platform=h5`，取 B 站返回的 HLS(m3u8) 地址 |
| 播放器 | 复用 `TxVideoView`（系统 VideoView 硬解 m3u8），App 内全屏播放 |
| 控制 | 播放/暂停、进度拖动（MediaController）、弹幕开关、画质切换（原画/高清/流畅）、返回、横竖屏 |

### 关键技术难点与解决

B 站直播 HLS 流有两个坑，直接用 VideoView 播会失败：

1. **CDN 防盗链**：m3u8 和分片校验 Referer，系统 VideoView 无法设置请求头 → 新建**专用本地代理 `LiveProxy`**（`127.0.0.1` 随机端口），由它带 Referer/UA 转发。
2. **分片相对路径**：m3u8 里的 `.ts` 分片是相对地址 → `LiveProxy` 在返回播放列表时，把每个分片路径**改写为指向本代理的绝对地址**（`/seg?u=<编码后的CDN地址>`），分片请求再由代理转发并**边收边发（流式）**，首包即达、支持 Range。

该代理与点播用的 `LocalProxy` **完全分离**，不影响原有的点播播放链路。

### 端到端验证（真实网络实测）
- 分区 / 房间列表接口 `code=0`，返回正常数据
- 真实在播房间取到 m3u8，播放列表含 3 个分片
- 分片改写为代理地址后，带 Referer 转发可达（333KB TS 流，MPEG-TS 同步字节 `0x47` 正确）
- 全链路：**分区 → 房间 → m3u8 → 分片** 打通

## 二、需要如实说明的限制（实验版）

- **直播弹幕**：当前是本地视觉弹幕（欢迎语/氛围弹幕）叠加层，尚未接入 B 站直播的实时弹幕 WebSocket 协议。真实直播弹幕需要实现 `broadcastlv.chat.bilibili.com` 的握手/心跳/消息解析，可作为下一步迭代。弹幕可通过播放页「弹幕 开/关」按钮控制。
- **画质切换**：直播源 `platform=h5` 下原画/高清/流畅实际多为同一路 HLS 流，画质切换会重连房间，清晰度差异取决于主播推流。
- 直播接口为 B 站公开网页端接口，可能随官方风控策略变化；若某分区临时取不到流，可切换其他分区/房间重试。

## 三、验证结果

- **守卫**：341 项全通过（含新增 7 项直播内嵌防回退断言，以及双目标分屏/全屏差异保护）
- **单测**：11 套全 PASS（新增 `LiveM3u8Test` 8 项，覆盖分片路径解析/改写/URL 编码）
- **编译**：平板版、手机版均通过 `javac → d8 → aapt2 → 签名` 完整链路
- **APK**：两版签名校验 `Verifies`，直播类（`LiveActivity`/`LiveProxy`/直播 API）已正确打入 dex
- **网络实测**：直播全链路在真实网络下打通

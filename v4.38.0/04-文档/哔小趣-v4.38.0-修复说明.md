## ② 高分辨率（尤其 1080p）弱网专项优化

核心思路：**分辨率自动不锁死，提速来自「选对轨 + 填满管道 + 不白等」**，而不是把画质压低。新增纯逻辑类 `StreamTuner`（可单测），四项决策：

1. **带宽快降慢升** —— 旧算法 0.35 新 + 0.65 旧，网络从 10Mbps 掉到 1Mbps 时还在按高码率拉流，必然卡。现在掉速时新样本权重 **0.75**，立刻降码率；回升时权重仅 **0.2**，谨慎，不被一次快分片骗去冲高码率又卡死。
2. **弱网 1080p 多开一段** —— 单条 TCP 受 BDP 限制，弱网下常只跑到带宽的一半。弱网 + 1080p 时收敛到 **2 段**填满管道（单段太慢，三段在弱网反而互抢、多耗线程）。**设备能力仍是硬顶**：老设备（只支持 1 段）绝不硬开。
3. **按带宽选轨保底** —— 自动档按实测带宽压到扛得住的档：极弱网 360P / 弱网 480P / 中等 720P，快网不压。带宽未知时不擅自改画质。
4. **看门狗自适应** —— 弱网 / 超流畅档放宽首帧等待（最长 **14s 硬上限**），避免过早回退合流造成二次卡顿和黑屏感；真拉不下来时仍有兜底，不会一直干等。

原有的竞速选路、预热、磁盘缓存、连滑预取、音轨延后、卡顿冻结音频等成熟优化全部保留。

## ③ 线程 / 端口 / 带宽加大

| 项目 | 调整 | 作用 |
|---|---|---|
| HTTP 连接池上限 | 16 → **24** | 并行段 + 视频 + 音轨 + 预取 + 接口同时复用，少做 TLS 握手 |
| 各档连接/线程 | 超清晰 24/12、平衡 18/10、超流畅 10/5、节能 6/3 | 档位越高给越多资源，老设备档保持精简 |
| 端口 backlog | 256、缓冲 1MB | 换片瞬间旧连接未退、新连接涌入不会被拒在门外 |

连接池上限扩大后，超清晰档在快网下能真正吃满带宽。

## ④ 播放调度可靠生效（必要时重启）

- 找到「调度没正常应用」的根因：`http.maxConnections` 是 **JVM 启动期属性**，运行中改只影响之后新建的连接；代理 IO 线程池也在构造时固定。所以切换调度后，部分参数要到下次播放甚至重启才干净生效。
- 现在切换任意调度档 / 保存自定义档后，会弹窗提示**「立即重启」**：重启让新调度从第一条视频就按新参数运行。也保留「稍后」，不强制打断。
- 五档（超流畅 / 超清晰 / 平衡推荐 / 节能 / 自定义）保留不变。

**超流畅弱网保底**：480P 封顶 + 单段低功耗 + 弱网选轨保底 + 看门狗放宽 + 起播海报铺底，目标是**弱网不卡、不加载久、不黑屏、不卡死**。

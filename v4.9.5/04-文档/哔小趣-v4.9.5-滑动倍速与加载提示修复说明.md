# 哔小趣 v4.9.5 · 竖屏滑动误触 2 倍速 / 加载提示清零

## 一、滑快就变「2× 快进中」——根因与修复

### 根因（不是玄学，是事件时序问题）

长按倍速由 `GestureDetector.onLongPress` 触发。`GestureDetector` 在收到 `ACTION_DOWN`
的那一刻就用 `Handler.postDelayed(..., 500ms)` 排好了长按计时器 —— **它不依赖后续的
MOVE 事件，500ms 一到自己就会响**。

而竖屏翻页的手势仲裁是这样的：

```java
if (swiping) {
    swipeOnMove(ev.getY());
    return true;          // ← 翻页期间不再把事件喂给 GestureDetector
}
```

于是快速上滑时出现这个链条：

1. `ACTION_DOWN` → 喂给 GestureDetector → 长按计时器启动（500ms）
2. 第二次 MOVE，位移超过 14dp → `swiping = true`
3. 之后所有 MOVE 都被 `return true` 拦下，**再也没有事件传给 GestureDetector**
4. 计时器没有被 CANCEL，500ms 后照样响 → `boosting = true`、`setRate(2.0f)`
5. 抬手时走的是 `swipeOnUp()` 后的提前 `return`，**永远到不了**
   `if (act == ACTION_UP && boosting)` 那行复位代码
6. 结果：`boosting` 残留，视频卡在 2×，直到下一次抬手才恢复

所以「滑得越快越容易触发」是必然的 —— 滑得快 ≈ 手指在屏幕上停留的绝对时间更长。

### 修复（三重保险）

| # | 位置 | 改动 |
| --- | --- | --- |
| 1 | `onLongPress` | 增加 `if (swipeMode \|\| swiping \|\| swipeDy != 0f) return;` —— 竖屏刷流下长按倍速直接禁用 |
| 2 | MOVE 判定 `swiping = true` 处 | 调用新增的 `cancelLongPressTimer(ev)`，给 GestureDetector 补一个 `ACTION_CANCEL`，主动掐掉已排定的计时器 |
| 3 | `swipeOnDown` / `ACTION_UP` 分支 | 无条件复位 `boosting = false` + 隐藏 `speedTag` + `setRate(1.0f)`，即使有残留也一定清掉 |

横屏与普通详情页的长按加速**不受影响**（那里 `swipeMode == false`）。

另外，`boosting` 为真时 `swipeMode && !swipeAnimating && !boosting` 会为假，
表现是「滑不动」；这次一并解决。

## 二、「加载中喵~」尽量降为零

上一版（v4.9.4）把竖屏延迟设为 1200ms，实测 4K/高码率视频起播本身就要 1.5～2.5s，
所以还是会露出来。

本次调整：

| 场景 | v4.9.4 | v4.9.5 |
| --- | --- | --- |
| 竖屏刷信息流 | 1200 ms | **3000 ms** |
| 普通详情页 / 横屏 | 160 ms | 160 ms |
| 打开离线缓存 | 200 ms | 200 ms |

配合原有的机制：`showLoadAnim(false)`（在 `onPrepared` 里调用）第一件事就是
`cancelLoadAnimSchedule()`，所以只要 3 秒内画面就绪，加载框**一次都不会上屏**。

为什么是「延迟」而不是「缩短显示」：加载框一旦上屏，就会压住封面和人物；
3 秒的窗口足以覆盖预取命中后的正常起播，等于把「网络正常」这一整类情况直接归零。

预取链路本身没有退化：`prefetchSwipeNeighbors` 会为前后各 2 条预取
`playurl`（带 cid、带 qn）与封面，切换时 `BiliApi.playurl` 直接命中
`URL_CACHE`，不发网络请求。

# 哔小趣 v4.13.3 更新说明

> 基于 v4.13.2 基线，versionCode 71 / 4.13.3，签名与历版一致可直接覆盖安装，
> minSdk 22（Android 5.1）兼容保持。

## 一、番剧播不出来 —— 破解

### 现象
点新番/番剧类视频（如「【3月】鬼灭之刃 游郭篇 01上【独家正版】」），
底部显示「**播放失败：该视频不存在或已失效**」（对应接口 code=-404）。

### 根因
这类是 **PGC / 版权番剧内容**。原播放地址链路只有三条普通接口：
`x/player/wbi/playurl` → 旧 `x/player/playurl` → html5 兜底。
普通接口对番剧内容统一返回 **-404「啥都木有/已失效」**，三条全挂 → 播放失败。
但其实番剧有**专用播放接口** `pgc/player/web/playurl`，实测 code=0 且返回完整 DASH 流。

### 破解做法
在 `BiliApi.playurlFetch()` 的普通链失败后，新增 **PGC 专用链**（置于 html5 兜底之前）：

```
https://api.bilibili.com/pgc/player/web/playurl?bvid=&cid=&qn=&fnval=4048&fourk=1
（Referer 指向 bangumi 播放页；响应字段是 result 而非 data）
```

- 番剧 bvid 的 cid 获取不受影响：`x/player/pagelist?bvid=` 实测正常返回。
- PGC 链拿到 result 后复用现有 `hasMedia()` 校验，命中即返回，后续挑流/播放逻辑完全不变。
- 普通视频仍走原来的链，行为不变；只有普通链全失败时才尝试 PGC，零副作用。

## 二、切栏目再点动态，动态串入其它视频

### 根因（两处）
`DynFeedView` 是跨 tab 复用的单例，切 tab 时会被 `removeAllViews()` **detach**：
1. **旧回调污染**：进行中的异步请求返回时视图可能已重新 attach，`alive()==true`，
   于是把「上一次/另一个分段」的数据 apply 进来 → 动态里出现别的视频。
2. **分段串数据**：点「全部/视频」分段切换时，若旧请求还在飞（`loading==true`），
   `load(true)` 被直接跳过 → 分段变了但数据还是旧分段的。

### 修复
- 新增**请求序号 `loadSeq`** + **分段快照 `typeAtRequest`**：每次请求带序号和发起时的分段，
  回调时若序号已被顶替、或分段已变化，直接丢弃，杜绝过期数据 apply。
- `switchType()` 切分段时强制 `loadSeq++` + 重置 `loading`，保证新分段一定能重新拉。
- 新增 `onDetachedFromWindow()` 打 `detachedSinceLoad` 标记；新增 `refreshOnShow()`：
  重新显示动态时若数据陈旧（detach 过 / 分段不符 / 空），强制按当前分段拉新鲜数据。
- MainActivity 的 `switchTab(1)` 和 `onResume` 改用 `refreshOnShow()`（原来是不刷新的
  `refreshIfEmpty()`）；构造 DynFeedView 时不再提前 load（未 attach 的请求必被丢弃，浪费且易串）。

## 校验
- API 22 编译 0 错误（497 class，Android 5.1 兼容保持）
- badging：versionCode 71 / 4.13.3 / minSdk 22
- v1+v2+v3 签名通过，证书 SHA-256 `0930aba7…` 与历版一致
- dex 命中 `refreshOnShow` / `onDetachedFromWindow` / `loadSeq` / `detachedSinceLoad` /
  `lastTypeLoaded` 及 `pgc/player/web/playurl` 字符串

## 说明
番剧破解走的是公开 PGC 播放接口，能播 B 站对当前账号/地区开放的部分（含大会员试看/已购内容）。
需大会员且当前账号无权限的正片，仍受服务端版权校验限制，任何第三方客户端都无法绕过——
这类会明确提示而非卡死。

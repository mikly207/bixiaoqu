## 一、液态玻璃：不是"半透明黑条"，是四层材质叠出来的

新建 `GlassPanel`（继承 `LinearLayout`，所以老的 `new LinearLayout(this)` 可以原地替换，子控件排布完全不用改），按真实光学顺序逐层绘制：

| 层 | 作用 | 实现 |
|---|---|---|
| ① 外投影（3 层递减） | 悬浮在画面之上 | 三层不同透明度的圆角矩形，越靠下越虚 |
| ② 主体染色（上浅下深） | 玻璃厚度 | 竖向三停靠渐变，浓度 75% |
| ③ **磨砂颗粒** | 玻璃 vs 半透明色块的分界 | 64×64 噪点 `BitmapShader` 平铺，alpha 26 |
| ④ 顶部柔光 + 左上径向反光 | 受光面 | `LinearGradient` + `RadialGradient` |
| ⑤ 底部内暗边 | 下缘折射 | 竖向渐变到 0x38 黑 |
| ⑥ 1dp 上亮下暗描边 | 棱 | 描边渐变 0x52 → 0x0D |
| ⑦ 按下提亮 / 显隐扫光 | 液态触感 | `isPressed()` 提亮；显隐时一道 720ms 斜向扫光 |

**为什么不做"真背景模糊"**：`RenderEffect` 要 API 31，本项目 minSdk 22；`PixelCopy` 抓视频帧要 API 24 且每次整帧回读（1080p ≈ 8MB 分配）。所以改用**浓度换可读性**，并且是量化过的：

> 实测同一点：亮画面背景 RGB(249,249,249) → 玻璃面板内 RGB(91,93,98)。
> 白字（#F2）在 #5B 上的对比度 ≈ **6.4:1**，远高于 4.5:1 的可读线；同时背后字形仍以低频轮廓透出来，正是磨砂玻璃该有的样子。

其它配套：
- **着色器按尺寸缓存**，静止时零重绘；扫光只在显隐那一刻跑一次（`onVisibilityChanged` + 1.2s 节流），不常驻动画。
- **模糊内核抽成 `GlassBlur`**，`LiquidNavBar` 删掉自己那份私有 box blur（-40 行重复像素循环）。
- **弹窗统一玻璃**：`glassDialog()` 只换 Window 背景（画质 / 倍速 / 更多 / 解码），内容布局一字未动，零风险。
- 切模式不再用 `setBackgroundColor` 盖实色，改成调玻璃浓度（浮在画面上 0xAA / 回到页面流 0xC6），否则圆角外面会露出方块底色。

## 四、启动速度

| 改动 | 之前 | 现在 |
|---|---|---|
| `DiskCache.init` | 主线程 `listFiles` + 逐个 `length()` + 淘汰扫描（缓存攒到几百 MB、几千个分片时 30~200ms） | 只建目录就返回；统计与淘汰交给 `bxq-cache-scan`（MIN_PRIORITY 守护线程） |
| `CrashHandler.note` | 每次 `open → write → close` 一个文件，冷启动约 10 次全在主线程 | 入队 + 后台 200ms 批量合并；崩溃时 `flushPending()` 先刷盘再写 crash.txt，日志不丢 |
| 预取并发 | `Semaphore(2)`：4 条推荐地址要排两轮 | `Semaphore(3)`：基本同时就绪 |

## 五、带宽与加载

- **预取并发 2 → 3**：`playurl` 只是几百字节 JSON，并发 3 对带宽几乎无感，但能让 4 条预取不再排队（排队意味着用户点下去时才刚拿到地址，等于白预热）。
- **前两条推荐都预热 96KB 首片**（原来只有第一条）：首页/右栏前两条最可能被点，第二条现在也能"点哪播哪"。
- **代理 socket 收发缓冲 512KB**：默认只有几十 KB，高码率 4K 一秒 5~10MB 时 `write` 会频繁阻塞，上游 CDN 发送窗口跟着收缩；调大后单连接吞吐更稳。
- 保留既有机制：3 条线路竞速（16ms 错峰）、256KB 读缓冲、`Range` 透传与断流续传、400MB 磁盘缓存（key 用 URL path，跨会话可命中）。

**仍然不做 HTTP/2**：平台 `HttpURLConnection` 只支持 1.1，SDK 22 上没有 ALPN；要上 h2 得整条网络层换 OkHttp，风险远大于收益。
**仍然不上 ExoPlayer**：手工 `javac→d8→aapt2` 链路无 Gradle，media3 要拖十几个 AAR + Kotlin stdlib；而慢在"取址 / 选线路 / 等首片回源"，换播放器一分钱省不下来。

## 七、已知限制

1. 玻璃是"高浓度染色 + 磨砂颗粒"，不是实时高斯模糊（API 22 上做不到），背后画面只能透出低频轮廓。
2. 竖屏 360dp 极窄屏，输入框约 96dp，提示语会省略成 `发个弹幕…`；多 P 视频出现「选集」后会再窄一些。
3. 扫光动画在低端机首帧可能掉 1~2 帧（只在控制条显隐瞬间跑一次）。
4. 磁盘缓存对单分片 >48MB 的长视频不生效（3 分钟内竖屏 720P 约 15~30MB，可命中）。

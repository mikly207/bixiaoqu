## 一、竖屏视频播放界面改成 B 站竖屏样式

竖屏视频（画面比高 > 宽）在竖屏持机时进入沉浸式界面，控件浮在画面上、画面铺满整屏：

- **右侧竖排**：头像（带粉色「+」关注徽标，关注后变「✓」）· 点赞 · 评论 · 投币 · 收藏 · 分享，图标下方带计数，选中态与原来那套完全同步（同一次点赞，两处一起变）。
- **底部信息条**：视频标题（最多两行）→ `UP主 · 昵称`（点进主页）→ 工具行 `播放/暂停 · 当前时间 · 弹幕开关 · 弹幕输入框 · 选集 · 倍速 · 全屏`。
- **最底部**：2dp 细进度条贴着屏幕下沿，可直接拖动。
- **顶部**：只留返回键 + 右上「更多」（更多里新增 **清晰度**，加上原来的 解码方式 / 缓存 / 复制链接）。
- **单击画面**：整组控件隐藏 / 显示一次切换（只留画面）。
- 原来那套「顶部五个图标 + 底部大工具条」在竖屏沉浸模式下不再出现；退出沉浸（返回键）回到详情页，控制条照旧。

翻页时的排版也一起对齐了：帖子标题不再贴在封面海报上（会和底部信息条打架），切到新视频时底部标题立即换成新视频的，不等接口往返。

## 二、上下滑动的流畅度

1. **滑动时暂停弹幕**：弹幕是整屏文字高频重绘（80ms 一次 invalidate），和跟手位移动画抢合成时间。现在手指真开始拖（位移 > 10dp）才把弹幕层隐去、停止推进，松手翻页结束自动恢复，不丢开关状态。
2. **海报提前贴进 View**：以前图片只做了「预取到内存」，滑动第一帧才 `setImageBitmap` + 纹理上传，正好落在最吃帧的时刻 —— 手感就是「第一下顿一下」。现在切完视频就把相邻两槽的封面、位置准备好，拖动时只有位移，没有解码和上传。
3. **不再解码用不到的大图**：竖屏沉浸模式下背景虚化图（bgCover）根本不显示，切视频时跳过它的整屏解码，少一次 GC 压力。
4. **标题从海报层移除**：少一层文字绘制，海报淡出更干净。

## 三、起播与切换速度

1. **线路预热更早、更全**：首帧出来 200ms（原 800ms）就探相邻两条（上一条 + 下一条）的 CDN，握手只读 1KB，不抢当前视频带宽；探到的最快线路会被代理记成亲和线路，滑过去直接走它。
2. **预取等待窗口 1200ms → 300ms**：预取正常 200~400ms 就回来；超过 300ms 还没回就自己发请求，不再干等 —— 「点开→起播」的最坏情况少了一秒。
3. 相邻 ±3 条的 playurl 预取、`QN_ALL` 一次取全档位、本地秒切清晰度等 v4.18.0 的机制保持不变。

## 四、验证情况

- 两版均全量编译通过（平板 667 个 class / 手机 659 个 class），d8 + aapt2 + zipalign + v1/v2/v3 签名完成，`apksigner verify` 通过。
- dex 抽检确认新类/新方法（`buildImmersiveUi`、`suspendDm`、`warmupOne`、清晰度菜单等）已入库。
- 装机后建议核对：竖屏打开任意竖屏视频 → 右侧栏与底部条是否就位；单击画面是否整组隐藏；上下连滑 10 条是否掉帧；日志 `perf` 里起播耗时是否 ≤ 2 秒（`adb logcat -s bxq`）。

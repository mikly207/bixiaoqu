## 一、重要澄清：互动其实一直是真实 API

接手排查后确认：交接包 README「已知限制」里写的「互动是本地模拟、未接真实账号 API」**与源码不符，属于过时描述**。

源码里 `BiliApi.setLike / addCoin / dealFav / modifyFollow` 早已是带 `csrf(bili_jct)` 的真实 POST，登录态链路（WebView 登录 → SharedPreferences → 启动注入 Cookie → 请求携带）完整可用。2026-11-24 实测四个互动 POST 端点与 view 接口均正常（未登录返回 `-101` = 端点有效、只差登录态）。

因此本次没有做「从零接入真实 API」这种重复劳动，而是**加固现有真实 API 的稳定性**，修掉 3 个真实存在的隐患。

---

## 二、本次修了什么

| # | 问题 | 修复 |
|---|---|---|
| 1 | **风控 412 无重试**：点赞/投币/收藏/关注/发弹幕全走 `postForm`，遇 B站 412 风控直接抛 `HTTP 412` 失败（互动恰恰最易触发风控） | `postForm` 加入与 GET 一致的一次性自愈重试：重取设备指纹 + 重新 `primeCookies()` 后重试，仍失败给出可读提示 |
| 2 | **登录过期无感知**：SESSDATA 过期后接口返回 `-101/-400/-403`，旧版只弹「点赞失败：账号未登录」，用户不知道要重新登录，本地失效 Cookie 也不清理 | 新增 `LoginExpired` 异常 + `checkWrite()` 统一业务码校验；识别登录失效后，UI 层自动清除内存与 SharedPreferences 中的失效登录态，引导重新登录 |
| 3 | **一键三连「假成功」**：旧版把每个 API 调用的异常全部 `catch(ignore)` 吞掉，再无条件把图标改成已赞/已投/已藏——即使全部失败也显示成功 | 逐个动作独立跟踪成败，只有服务端确认成功才更新对应 UI；失败项汇总真实原因，登录过期统一走清理流程；全成功才提示「三连成功」 |

> 曾考虑补「收藏状态回显」（加载时回显已收藏），但实测 B站收藏状态查询接口需真实登录态且路径不稳定，无真机登录态无法验证，为避免引入 bug 本次**未做**。

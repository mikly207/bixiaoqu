# 哔小趣 v4.9.4 · 竖屏刷流加载提示精简

## 你提到的现象

竖屏上下滑刷视频时，画面正中央会弹出一个半透明黑色药丸：

> 正在切换...

遮挡人物主体，而且停留时间明显偏长（一直挂到新视频画面出来为止）。

## 这次改了什么

### 1. 文案换成「加载中喵~」

全应用统一：

| 位置 | 旧 | 新 |
| --- | --- | --- |
| 加载框主文案 | 正在加载喵~ / 正在切换… | **加载中喵~** |
| 默认 `playLoadMsg` | 正在加载喵~ | 加载中喵~ |
| 加载框初始构建文案 | 正在加载喵~ | 加载中喵~ |

`正在切换…` 这个字符串已经从代码和 dex 里彻底移除（已校验：dex 中命中 0 次）。

### 2. 加载框「延迟上屏」，把可见时间压到接近零

核心思路：**不是让它消失得更快，而是让它根本来不及出现。**

新增 `scheduleLoadAnim(msg, delayMs)` 与 `cancelLoadAnimSchedule()`：

- 进入 `play()` 时不再立刻 `showLoadAnim(true)`，而是挂一个延迟任务。
- 画面 `onPrepared` 时执行 `showLoadAnim(false)`，该函数第一件事就是 **取消挂起的延迟任务**。
- 于是：首帧先到 → 任务作废 → 加载框一次都没上过屏，零闪烁。

延迟档位按场景区分：

| 场景 | 延迟 | 说明 |
| --- | --- | --- |
| 竖屏刷信息流（`swipeMode` / `portraitFill`） | **1200 ms** | 有封面海报兜底，画面不黑，正常网络下基本永不出现 |
| 普通详情页 / 横屏 | 160 ms | 仍保留必要的等待反馈 |
| 打开离线缓存 | 200 ms | 本地文件起播极快，通常也看不到 |

连续快速翻页时，每次新的 `play()` 都会 cancel 上一个计时重新计，所以连滑过程中加载框会一直不出现。

### 3. 竖屏沉浸下不再弹技术性提示文字

原来切视频时画面中间还会打下这两行白字：

- `获取播放地址…`
- `切换到 BV1xxxx …`

现在竖屏沉浸模式下直接置空，只有**真正的错误**（`播放失败：…`、`切换线路 x/y 重试中喵~`）才会显示。横屏与普通详情页维持原样。

## 效果预期

- 正常网络（playurl 已预取命中）：翻页 = 封面滑入 → 画面直接接上，中间**没有任何加载字样**。
- 网络偏慢（> 1.2 s）：才会在中央浮出一枚「加载中喵~」，画面一就绪立即消失。
- 不会再有「闪一下就没」的闪烁，因为要么不出现，要么稳定显示到就绪。

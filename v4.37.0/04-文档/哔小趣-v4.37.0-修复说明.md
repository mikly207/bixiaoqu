## ① 五个图标重做 —— 严格按参考图，纯实心饱满

上一版"没达到效果"的根因：**收藏做成了空心描边星、转发做成了细线描边箭头**，而你发的照片里这两个都是**实心面块**。

本版逐个对照照片重绘：

| 图标 | 参考图样子 | 本版实现 |
|---|---|---|
| 点赞 | 实心大拇指 + 独立圆角底座 | 纯实心拇指面块，靠 tint 切选中色 |
| 评论 | 实心圆角气泡 + 三条横线 | 实心气泡，evenOdd 镂空三条横线 |
| 投币 | 白色实心圆盘 + 深色 ¥ | 实心圆盘，evenOdd 镂空标准 ¥（Y 形 + 两横 + 一竖） |
| 收藏 | 实心五角星 | 纯实心星 + 同色圆角描边（角更饱满） |
| 转发 | 实心弯箭头 | 纯实心弯箭头，无描边细线 |

浅色模式可读性沿用并保留：`idleActColor()` 让底部互动栏图标跟随主文字色（浅色下变深色），压在视频上的横屏栏仍用白色，不再出现"白底白图标"。

> 五个图标两版资源完全一致；已用 SVG 逐图标渲染核对形状，并做 aapt2 完整 link 预检通过。

## ③ 自动分辨率前提下提速、减卡顿

关键事实：工程里早有一套 `StartupDiag.adaptHeight()`（按实测带宽自动选档）写好了却**从未接入播放链路**，默认画质反而写死 720P——既不是真自动，也没利用上带宽数据。本版把它接通：

1. **带宽自适应选档（新类 `LoadTuner`）**
   - 自动档下按实测带宽挑"扛得住的最高档"：快网给高清、弱网给流畅
   - 设备能力 / 调度档位上限始终是硬顶，绝不盲目冲软解 4K（软解 4K 正是"有声音没画面/首帧永远出不来"的主因）
   - `BiliApi.estBandwidth()` 暴露平滑后的实测带宽；`adaptHeight` 从"空置"变成主链路在用
   - **提速不靠锁低画质**：分辨率全程自动，省的是"选错轨 + 白等"的时间

2. **一次取回全部清晰度**
   - playurl 仍请求最高可用，`pickVideo` 本地选轨，切画质秒切、不重复发网络请求

3. **起播让路窗口自适应**
   - 首帧到达后，预取/详情/弹幕的放行时机由首帧实测耗时决定：
     - 首帧 ≤1200ms（快网）→ 500ms 就放行，连滑下一条更快
     - 首帧 ≥2200ms（慢网）→ 保护 1200ms，避免二次抢占把刚起播的视频拖卡
   - 已在`起播保护 → 首帧收口 → 恢复并行`的完整链路上生效

4. **去冗余**
   - 删除两处固定的 `endStartup(1200)`，统一由 `noteStartupCost()` 按首帧耗时决策，避免多处重复设置让路窗口

> 加载链路里原有的四线路竞速、首片预热、磁盘缓存、连滑预取等优化全部保留，本版是在其上做"自动分辨率 + 让路自适应"的增量改进。

# 哔小趣 v4.13.12 更新说明

> 主题：**全新优化竖屏滑播——删掉拖慢加载的预缓冲，改为起播前置 + 海报清晰化**
> 版本：v4.13.12（versionCode 80）· minSdk 22（Android 5.1）· 适配至 Android 17

---

## 先说 v4.13.11 为什么更糟（已全部删除）

上一版试图在后台把相邻视频的首片数据预先下载到本地代理缓存。实测这个方向是错的：

- 它对前后各 3 条视频同时下载首片，**抢占了当前正在播放视频的带宽**，起播反而更慢；
- 缓存命中后的「内存首片 + 网络续传」拼接逻辑有截断风险，一旦续传失败，播放器拿不到完整数据 → 卡在「加载中喵~」；
- 还额外引入了 4 个 class 和一整套线程/缓存/闸门代码。

**v4.13.12 从干净基线重做，这套预缓冲代码（LocalProxy 缓存、prebuffer、PlayActivity 调用）已 100% 移除**，class 数从 509 回到 505。

## 这次的全新优化（3 项）

### 1. 起播前置 —— 把等待藏进翻页动画里（核心）

原来的时序是**串行**的：

```
手指上滑 → 220ms 位移动画 → 动画结束才切视频 → 取地址→建连→CDN竞速→解码首帧 → 出画
```

「糊封面」停留的时长，基本就是动画结束后那一段建连+解码时间。

现在改为**并行**：

```
手指上滑 → 动画开始就切视频并起播 ─┐
                                    ├─ 同时进行 → 动画结束时首帧多半已就绪 → 直接出画
         220ms 位移动画 ────────────┘
```

取地址、建连、CDN 竞速、首帧解码与位移动画重叠进行，省掉整整一段串行等待。这是「滑到即播」最有效、且不动网络链路的做法。

### 2. 海报淡出时机对齐动画（防黑屏闪烁）

起播提前后，首帧可能在动画还没结束时就已经渲染好。此时若立刻撤掉海报纸条，会露出仍在移动中的空槽（一闪黑屏）。

新增 `posterPendingAfterAnim` 标志：首帧在动画期间就绪时先记下，**等翻页动画归位后再淡出海报**，衔接平滑。动画结束回调不再重复切换视频（消除 v4.13.11 遗留的重复起播隐患）。

### 3. 海报清晰化 —— 告别糊封面

全屏海报此前用 `@320w_200h` 横版小图拉伸铺满竖屏，必然发糊。新增竖版高清封面 `@720w_1280h_1c`，用于：

- 跟手预览（`prepareSwipePreview`）
- 翻页落定海报（`applySwipeSwitch`）
- 相邻封面预取（`prefetchCover`）

三者使用同一 URL，命中 ImgLoader 内存 LRU，不额外增加网络等待；解码尺寸按实际屏幕高度采样，不再二次降质。即使首帧尚未就绪，过渡画面也是清晰的。

## 说明

这次是「减法 + 时序优化」：删掉上一版拖慢加载的预缓冲，不再与当前视频抢带宽；把起播提前到与动画并行，让首帧在动画结束时基本就绪；同时把过渡封面从糊的小图换成竖版高清图。弱网下首帧仍需网络时间，但正常网络下应明显比 v4.13.11 快，糊封面停留大幅缩短。

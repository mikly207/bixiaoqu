## 一、本版修复的四个问题

### 1. 三国演义「只有标题没有内容」— 已彻底修复 ✅

**问题根因**（不是数据丢失，是切章逻辑写错了）：

构建脚本按 `第001回`（阿拉伯数字）去匹配回目，但三国演义的正文里
实际用的是**中文数字** `第一回`。两者对不上，于是：

| 回目 | 旧版正文长度 | 实际情况 |
|---|---|---|
| 第 1~119 回 | 58~64 字节 | 只有一行标题，**正文全空** |
| 第 120 回 | 1,803,143 字节 | 全书 60 万字正文**全塞在这一回** |

也就是说书里的字**一个字都没丢**，只是被错误地归到了最后一回。
旧版读第 1 回当然只有标题，读第 120 回才会看到一整本书。

**修复方式**：

1. 从第 120 回的 body 里取出完整正文（603,635 字）；
2. 按**中文数字回目**重新切成 120 回，逐一校验序号连续（1→120 无跳号、无重复）；
3. 重建 `sanguoyanyi.bin.gz` + `sanguoyanyi.idx.json`；
4. 全量复检：120 回**零空章**，最短回 2,831 字，最长回 7,402 字。

**字数对比（一个字不少）**：

| 书名 | 回数 | 字数 | 空章 |
|---|---|---|---|
| 西游记 | 100 回 | 725,244 字 | 0 |
| 三国演义 | 120 回 | 603,394 字 | 0 |
| 红楼梦 | 120 回 | 873,897 字 | 0 |
| 水浒传 | 120 回 | 928,456 字 | 0 |
| **合计** | **460 回** | **3,130,991 字** | **0** |

> 三国演义比旧版统计少 2,946 字，是**标题格式归一**的结果：
> 旧标题是 `第001回 宴桃园…`，新标题是 `第一回 宴桃园…`，
> 120 个标题各少 24~25 字符 ≈ 2,946。正文内容**一字未动**。

### 2. 小说翻页逻辑 — 全面重做 ✅

旧版有 6 个实际影响阅读体验的问题，这一版全部解决：

| 旧版问题 | 本版做法 |
|---|---|
| 整章一次性 `setText`，长章节（4 万字）明显卡顿 | **分段渲染**：每 1500 字一批追加到缓冲区，批间让出一帧，UI 全程可响应 |
| ScrollView 挂 `OnTouchListener`，抬手时 x 在左右 28%/72% 就翻章 —— **想滑动看正文，手一抬就跳章** | **彻底移除该监听**。滚动只负责滚动，翻章只由底栏按钮 / 滑到底触发 |
| 翻章用 `smoothScrollTo(0,0)`，从长章节底部平滑滚回顶部要好几秒 | 翻章改为**瞬时 `scrollTo(0,0)`**，符合直觉 |
| 字号、护眼模式不持久化，每次打开都回默认值 | 全部写入 SharedPreferences，下次打开原样恢复 |
| 不记住读到哪一章的第几行 | **每本书独立记住「章节号 + 章内滚动位置」**，退出再进来原地续读 |
| 没有进度反馈，也不知道本章多长 | 顶部加细进度条，底部显示「本章字数 / 全书回数 / 已读百分比」 |

另外两处细节优化：

- **目录改用 ListView**：旧版一次创建 120+ 个 TextView，低端机打开目录会顿；
  现在复用条目，打开后自动定位到当前章附近。
- **预取下一章**：读完本章时后台静默加载下一章，翻章不再等待。

### 3. 留声机顶栏图标拥挤 — 已修复 ✅

- 在线转 MP3 · 软件内视频取音轨
- QQ 音乐 · 跳到官方客户端

无论手机还是平板，顶栏宽度恒定，不再拥挤。

## 二、愤怒的小鸟 — 完全重写 🎮

用户单独点名要求重做，这一版是整份代码重写，不是打补丁。

### 抛物线：预测线与真实飞行**严格一致**

这是旧版最致命的问题。旧版预测线用解析解
`py = by + pvy*t + 0.5*G*t²` 硬算，真实飞行却用逐帧欧拉积分
`vy += G*s; by += vy*s` —— **两者根本对不上**，玩家照着预测线打必然偏。

**本版方案**：抽出**唯一一份**积分器 `integrate()`，预测线与真实飞行
调用**完全相同的函数、相同的步长、相同的常量**。

| 改动 | 说明 |
|---|---|
| 固定子步长积分 | 1/240 秒固定步长，**帧率无关**（120Hz 屏和 30Hz 屏弹道完全相同） |
| 子步长累加器 | 帧边界的余量攒到下一帧继续用，保证步长序列严格一致 |
| 半隐式欧拉 | 先更新速度再更新位置，比显式欧拉精度高一个量级 |
| 线性空气阻力 | 高抛物线更「飘」、低平弹道更快，接近真实弹弓手感 |
| 初速按拖拽距离换算 | 拖多远 = 多大力度（带曲线），角度由拖拽方向决定 |
| 小鸟随速度方向旋转 | 落地后翻滚，有实感 |

**量化验证**（`tools/BirdTrajectoryTest.java`，JVM 实跑）：

```
【1】预测线 vs 真实落点
拉拽偏移            预测落点      实际落点      误差px    仰角
(-180,  90)          989.6       990.0       0.00    26.6°  [30fps 0.00 120fps 0.00]
(-260, 150)         1778.6      1785.1       0.00    30.0°  [30fps 0.00 120fps 0.00]
(-390, 280)         3004.1      3004.1       0.00    35.7°  [30fps 0.00 120fps 0.00]
最大误差：0.000 px
```

12 组拖拽组合全部 **0.000 px 误差**，且 30 / 60 / 120 fps 三种帧率落点完全相同。
射程扫掠确认：最大射程 2,985 px（塔距 1,178 px），拖拽空间内存在命中塔心的解。

> 顺带修掉一个**方向反了**的 bug：旧版 `launchVelocity` 的符号约定与调用处
> 不一致，小鸟会被弹向错误方向。

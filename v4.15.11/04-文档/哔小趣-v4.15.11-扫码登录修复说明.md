# 哔小趣 v4.15.11 更新说明（扫码登录：生成 → 登录）

**版本**：v4.15.11（versionCode 107）
**兼容**：Android 5.1（API 22）及以上
**签名**：证书不变（SHA-256 前缀 `0930aba7…`），可直接覆盖安装

---

## 一、先解决「二维码生成不出来」

### 现象
扫码页一直停在「正在生成二维码…」，久等无结果。

### 原因
App 用 `HttpURLConnection` 直连 `passport.bilibili.com` 生成二维码，原超时是 连接 15s + 读取 30s，
两条线路 × 3 次重试 → 最坏要 4 分钟以上才报错，期间界面没有任何变化，看起来就是卡死。
部分网络环境下这条直连链路本身就不通（DNS/网关/TLS 任一环节），再久也等不到。

### 修复
| 改动 | 说明 |
| --- | --- |
| **超时收紧** | 直连改为 连接 6s + 读取 8s；失败 10 秒级就能看到结果 |
| **重试次数下调** | 3 次 → 2 次（单次调用内部已含多线路，不必外层再翻倍） |
| **云端兜底通道** | 直连两条都不通时，改用**已验证可用的服务端接口**生成二维码（与网页版同一套），App 只负责展示与轮询 |
| **失败记忆** | 一旦判定直连不通，下次打开扫码页**直接走云端秒出码**，不再每次干等 |
| **进度提示** | 生成期间每 2 秒刷新「正在连接 B 站…（Ns）」，失败会显示具体原因，不再像卡死 |

> 云端通道实测：生成 `code=0` 返回 key 与扫码 URL，轮询返回 `86101`（未扫码）状态机正常。

## 二、再解决「扫完登不上 / 凭据失效」

| 改动 | 说明 |
| --- | --- |
| **凭据取值顺序** | `Set-Cookie` 原值 → `data.url` 原样参数 → URL 解码参数（不再优先用解码值，`%2C` 保持编码态） |
| **完整 Cookie 入库** | 云端通道返回 `creds.raw`（含 `SESSDATA / bili_jct / DedeUserID / DedeUserID__ckMd5 / sid`），整串解析进 Cookie 表 |
| **登录态实测** | 确认后调 `navInfo()` 读 **`data.isLogin`**（B 站登录态在 data 节点内），会话生效延迟则最多重试 4 次（约 6 秒） |
| **持久化完整 Cookie** | 新增 `full_cookie` 字段；重启 App 用 `addCookie()` 恢复全套，不再只剩三件套 |
| **`addCookie` 解析修复** | 旧实现只按第一个 `=` 切分，`"a=1; b=2"` 会把后面字段全塞进 value；现按 `;` 分段解析 |
| **`_uuid` 设备指纹** | 缺失时按 B 站同构格式生成并全程复用，避免「认得出账号、不认可会话」 |
| **Origin 按域下发** | 访问 passport 域时 Origin 用 `https://passport.*`，不再一律 `www.bilibili.com` |

成功提示为「登录成功 ✓ 昵称」并自动关闭页面；若凭据已存但登录态未确认，会明确提示而不是假装成功。

## 四、验证方式

1. 装新版 → `我的 → 登录 → 二维码登录`；
2. 前几秒会显示「正在连接 B 站…（Ns）」，**最长约 20 秒内必出码**（直连不通会自动切云端）；
3. 手机 B 站 App 扫码并在手机上点「确认登录」；
4. 页面提示「登录成功 ✓ 昵称」即完成，头像与昵称会同步。

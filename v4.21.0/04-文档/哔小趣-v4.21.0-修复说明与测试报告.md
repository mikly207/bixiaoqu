# 哔小趣 v4.21.0 · 平板版黑屏 / 变竖屏 修复说明与测试报告

> 版本：4.21.0（versionCode 121） · 两版：平板版 / 手机版 · 包名相同，互斥覆盖安装

---

## 一、你反馈的现象，逐条对应到了代码

| 现象 | 真正的原因 |
|---|---|
| 横屏分屏里点右侧推荐，**有概率黑屏只剩声音** | 新视频的详情接口回来后执行了 `enterPortraitFill()`，在**横向 root** 上把 holder 改成「整屏 + weight」，右栏被挤成 0 宽；画面盒按整屏重算 → SurfaceView 在 `prepareAsync` 期间被重新测量 → Surface 重建，解码器不再出图。声音走的是独立音轨，所以照常在放 |
| **再返回一下，变成手机版竖屏** | `exitPortraitFill()` 只还原「详情页」的尺寸（holder 230dp、视频按比例居中），分屏不会自己回来；平板上这个详情页就是截图里那条窄视频 + 一大片黑底 |
| 偶发「卡死」 | 铺满时同时执行了 `enterSwipeMode()`，翻页层的触摸监听留在分屏左栏上，右栏点击/滑动被吃掉 |
| 黑屏一直不恢复 | 首帧看门狗用 `isPlaying() && pos > 800` 判断「已出帧」。黑屏时进度照样走（音轨独立），于是被误判成「已出帧」，看门狗从不介入 |
| 解码器偶发不释放 | `VideoView.stopPlayback()` 内部是 `stop()` → `release()`；在 **PREPARING** 状态调 `stop()` 会抛 `IllegalStateException`，`release()` 被跳过，旧硬解实例留在系统里 |

关键 bug 就是这一行（v4.20.0 `applyMeta`）：

```java
// 旧：只判了「竖屏视频 + 非全屏」，没判分屏 / 横屏
if (portraitVideo && !fullscreen) enterPortraitFill();
```

## 二、这次改了什么

### 1. 布局判断集中到一个纯逻辑类（可脱离设备测试）

新增 `LayoutPolicy.java`，所有「该不该铺满 / 该不该分屏 / 返回键做什么 / 画面盒多大」都只从这一处出：

```java
public static boolean canPortraitFill(boolean portraitVideo, boolean pref,
                                      boolean split, boolean fullscreen, boolean landscape) {
    return portraitVideo && pref && !split && !fullscreen && !landscape;
}
```

`onCreate` / `applyMeta` / `playurl` 宽高回调 / 退出全屏 / 旋转，全部改为调用 `maybePortraitFill()`；`enterPortraitFill()` 自己也加了 `splitMode` 与横屏硬门槛（双保险，任何漏网的调用都会被拒绝并写日志）。

### 2. 分屏在换视频时「一根手指都不许动」

- `switchVideo` 不再调用 `exitPortraitFill()` / `exitSplitMode()`，只重算左栏画面盒；
- 新增 `applySplitSizeNow()`：**在 `setVideoPath` 之前**把盒子摆对，避免 prepare 中途改尺寸；
- 推荐项的 `aspect` 直接带进播放页，第一帧之前尺寸就是对的；
- 盒子尺寸没变时直接 return，不触发多余的 `requestLayout`（少一次重测，就少一次 Surface 重建的机会）；
- `enterSplitMode` 里顺手关掉残留的竖屏翻页。

### 3. 返回键：分屏直接离开播放页

```java
public static int backAction(boolean split, boolean fullscreen, boolean fill) {
    if (fullscreen) return BACK_EXIT_FULL;
    if (fill) return BACK_EXIT_FILL;
    return BACK_FINISH;      // 分屏不再退回「手机版详情页」
}
```

### 4. 黑屏只剩声音：三道防线

1. **根因**：分屏/横屏下不再进入铺满 → 不再重排 Surface；
2. **解码器**：`TxVideoView.reset()` 增加反射兜底，`stopPlayback()` 异常时强制 `reset()+release()` 内部 `mMediaPlayer`；
3. **兜底**：首帧判定改为「视图有尺寸 + 在窗口上可见 + 真的出帧」，看门狗发现「进度在走但无画面」时先修尺寸、再回退/重建 Surface 重播，并从当前进度续播（不从头开始）。看门狗全部加了代际保护，换片后旧计时器不再干扰新视频。

### 5. 起播海报不再「盖住已出画的视频」

旧版是 `play()` 里 post 一个贴图任务，prepared 抢先时海报会在出画之后贴上来，然后一直盖到 8 秒兜底 —— 这也是「黑屏但有声音」。现在贴图前必须过 `shouldShowPoster(首帧已到, 播放器已就绪, 切档中, 暂停切档)`，任何一个成立就放弃；失败路径也会主动撤掉海报。

### 6. 音画同步

音轨起播位置统一走 `audioStartTarget(pending, videoPos)`：没有断点时对齐画面当前进度，不再拿 `-1` 直接 seek；换片时 `releaseAudio()` 已把断点清零，不会把上一条的时间点带到新视频。

### 4. 说明（不回避）

沙箱里没有可用的 Android 模拟器（无 KVM，无法跑 x86 镜像），所以**没有做像素级真机/模拟器回放**。上面的测试是「布局状态机 + 事件时间线」级别的模拟：它能在毫秒级穷举所有模式组合，证明「分屏绝不会再被改成竖屏铺满」「画面盒不会算出 0 尺寸」「海报不会盖在已出画的视频上」，但**解码器与 Surface 的真实行为仍以你机器为准**。

## 四、装机后请按这 6 步验收

1. 平板横屏，进任意横屏视频（自动分屏），**连续点右栏 5 个推荐** → 不应黑屏、右栏不能消失。
2. 其中点一个**竖屏**推荐 → 左栏应显示「竖屏居中、上下留黑边」，不能跳成全屏，也不能出现窄条手机版。
3. 在分屏里按返回 → **直接回列表**（不再出现截图 2/3 那种页面）。
4. 全屏 ↔ 分屏 连点 5 次（间隔 <1 秒）→ 布局不错位、不重播。
5. 竖屏持机看竖屏视频 → 沉浸式；转横屏 → 分屏；再转回竖屏 → 沉浸式。
6. 看日志（设置里可导出）：
   - 出现 `[watch] 无画面` 说明仍有一次兜底介入，请把那几行发我；
   - 出现 `[portraitFill] 拒绝进入：分屏中` 说明还有别的路径在调铺满，也请发我；
   - `[perf] 首帧 xxx ms` 是「点开→出画」耗时，正常应 < 1200ms。

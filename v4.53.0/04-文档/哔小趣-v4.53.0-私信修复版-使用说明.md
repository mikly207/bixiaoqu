# 哔小趣 · 离线激活码方案（v4.53.0）

> 一句话：**用户付款把设备 ID 发你 → 你用一个生成器软件出激活码 → 用户粘贴即解锁。**
> 全程不联网、不服务器、不内网穿透，用户在哪个地区都能用。

---

## 一、为什么改成这样

之前几版都在折腾"服务器校验 / 局域网控制台 / 内网穿透"，越搞越复杂，而且有个绕不开的矛盾：

- 静态收款码没有支付回调，钱到账你这边**不会自动收到通知**；
- 作者手机开的服务是局域网地址，异地用户根本连不上；
- 内网穿透地址会变，用户装好的 App 就失效了。

现在彻底绕开这些：**你亲眼看到到账截图才算数**，然后亲手发一个激活码给用户。
激活码用你的私钥签名，App 里只放公钥验签 —— 用户伪造不出来，也不用连任何服务器。

---

## 二、三方各自的体验

| 角色 | 要做的事 |
|---|---|
| **用户** | 付款 → 在 App 里复制「设备 ID」发给你 → 收到激活码 → 粘贴进 App → 解锁 |
| **你（作者）** | 看到到账截图 → 打开生成器 → 填设备 ID → 生成激活码 → 发给用户 |
| **不需要** | ❌ 服务器 ❌ 域名 ❌ 内网穿透 ❌ 同一 WiFi ❌ 用户填任何配置 |

## 四、完整操作流程

**第 1 步**：用户打开 App → 点「登录」→「去捐赠解锁」，
在「支持我们」页复制自己的 **设备 ID** 发给你（连同付款截图）。

**第 2 步**：你确认到账后，打开生成器：
- 填入用户的设备 ID
- 填金额（默认 10）
- 选支付方式、有效期（默认永久）
- 点「生成激活码」→「复制」

**第 3 步**：把激活码（一串 `BXQ1-` 开头的字符）发回给用户。

**第 4 步**：用户在 App「支持我们」页点「输入激活码，立即解锁」，
粘贴 → 提示成功 → 登录即可，全部功能开放。

## 六、安全性（简单说）

- 激活码 = 用你的**私钥**对「设备 ID + 金额 + 有效期」做 RSA 签名；
- App 里只有**公钥**，验签通过才认；
- 所以：改激活码 → 验签失败；换设备用 → 设备不符被拒；过期 → 失效；
- 用户就算反编译 App，也拿不到私钥，造不出有效激活码。

已做验证：正常码通过、换设备拒绝、篡改拒绝、去前缀拒绝、过期拒绝、兑换后登录放行（8 项 JVM 单测全过），且 APK 签名校验通过。

## 七、交接包里还有什么

- `哔小趣-v4.53.0私信修复版-源码.zip`：完整源码（含平板/手机/生成器工程 + 你的私钥备份）
- `作者私钥_勿外传/donate_priv.pem`：私钥单独备份（换电脑、重装生成器时用）
- `哔小趣-激活码生成器.html` / `.apk`：生成器两种形态

### 换电脑 / 重装生成器怎么办
私钥已在源码包 `_作者私钥_勿外传/` 里备份。生成器内置的就是这把私钥，
只要用同一把私钥签，用户手上 App 的公钥就能验过。**不要重新生成密钥**，
否则所有已发出去的激活码和已装 App 都要重来。

## 八、常见问题

**Q：用户输激活码提示"激活码无效"？**
A：① 确认完整复制（`BXQ1-` 开头，很长一串，别漏字符）；
② 必须在**收码的那台设备**上用（激活码绑定设备 ID）；
③ 确认是用你这把私钥生成的码，而不是别的版本。

**Q：用户卸载重装 App 后还能用吗？**
A：只要设备 ID 没变（App 会把设备 ID 存在本机），重装的码仍有效；
若设备 ID 变了，让他重新复制发你，你重新生成一个即可。

**Q：能设订阅/到期吗？**
A：生成器里选有效期即可（永久 / 1 年 / 30 天 / 7 天）。到期后用户需续费，你再发新码。

## v4.53.0 更新说明（当前版本）

私信体验修复，激活码方案与密钥完全不变（老激活码继续可用）：

- **一键已读 · 红点清除（重点修复）**：
  - 根因：旧版调用的 `x/v2/msg/feed/read` 接口在 api.bilibili.com 域对第三方客户端长期受限，返回 -404/-403，导致提示「部分接口受限」，服务端红点清不掉。
  - 修复：改用官方 `session_svr/v1/session_svr/update_ack`（api.vc.bilibili.com 域，与私信列表同域），这是 B 站网页私信真正使用的已读接口。
  - **本地红点立即清除**：点击后不等网络就先把列表小红点清掉并刷新——这是你点「一键已读」要的直接结果；服务端同步在后台并发进行（6 线程），成功与否只影响提示文案，绝不影响红点清除。
  - 提示如实反映同步结果：「已全部标记为已读」/「已清除红点（x/y 已同步服务端）」/「已清除红点（部分接口受限）」。
- **私信头像加载慢（多版本遗留问题，本次根治）**：
  - 根因A：批量名片接口 `user/cards` 常被风控返回空 → 退化为逐个串行请求最多 24 个，每个一次网络往返，极慢。
  - 根因B：只从公开名片接口取头像，忽略了会话接口本身已带的头像字段。
  - 修复：① 优先解析会话自带的 `account_info.pic_url` / `face`、`user_info`、`last_msg` 内头像字段，**零额外请求**直接显示；② 仍需回补的头像改为 **8 线程并发**拉取，补一个刷一个，不再串行等待；③ 回补任务走 NetPrio 后台调度，不抢 UI 与播放资源。
- 两个工程（平板/手机）同步修复，消息页逻辑一致。

> 本次只动私信（MsgActivity / BiliApi / NetPrio），捐赠/激活码/密钥一字未改。安全单测 18/18 通过。

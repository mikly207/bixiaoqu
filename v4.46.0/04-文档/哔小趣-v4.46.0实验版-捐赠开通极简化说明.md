# 哔小趣 v4.46.0 实验版 · 捐赠开通极简化

> **本版把「配置服务端地址和公钥」的活儿从终端用户身上彻底拿走。**
> 用户下载安装 → 扫码捐赠 → 自动开通，全程不需要填任何东西。

---

## 一、上一版的问题（已修正）

v4.45 修好了「点一下就解锁」的漏洞，但把配置复杂度**转嫁给了终端用户**：

- 设置页多了一整段「捐赠校验服务」，要用户填 **服务地址** 和 **校验公钥**
- 捐赠页点按钮弹出「未配置捐赠校验服务 → 请到设置里填写」
- 登录门禁同样弹「去设置」

用户是来用软件看视频的，凭什么要填 URL 和 Base64 密钥？既然「用户能找到这个软件已经十分不容易」，
就更不该在首次使用就摆出技术参数。

---

## 二、v4.46 做了什么

### 1. 配置全部前置到打包阶段（用户零配置）

新增 `DonateConfig.java` 作为服务端地址与公钥的**唯一内置位置**，由作者打包时写入一次。
设置页里的「捐赠校验服务」整段**已删除**，`Prefs` 里用户可改的服务端地址/公钥**也已移除**。

> 一键命令完成「部署 + 打包」：
> ```bash
> bash 一键部署打包.sh https://donate.example.com
> ```
> 自动生成密钥 → 写入内置配置 → 编译双 APK → 打印后续提示。

### 2. 捐赠页：申请开通 + 自动等待

按钮从「刷新支付状态」改为 **「我已支付，申请开通」**。点击后：

1. 自动向服务端创建订单并拿到订单号（页面上会显示，提示转账备注填它）
2. **自动每 2.5 秒查询一次**，最多约 2 分钟
3. 服务端一核销 → 页面立刻变成「✓ 感谢你的支持 · 已解锁」

用户不需要再点第二次，也不会看到「未收到支付记录」这种像责怪人的文案。

### 3. 登录门禁：已开通用户零等待

- **已确认过捐赠** → 直接放行（不连网、不转圈），同时后台静默向服务端刷新一次状态
- **回到首页** → 自动静默同步开通状态，用户在别处付的款，回来就生效，全程无弹窗
- **未开通** → 引导到捐赠页（仍是唯一必经步骤）

### 4. 作者未部署服务端时的兜底

若内置配置为空（作者还没执行一键打包脚本），App **不会**把用户拦在门外要求配置，
而是按自助开通处理，捐赠页也不会弹任何技术报错。

## 三、安全性没有削弱

**v4.45 堵死的「前端自证」漏洞在本版依然堵死**，且新增守卫断言防止回退：

| 检查项 | 结果 |
|---|---|
| 客户端存在置成功方法（`setDonated`）？ | **不存在** |
| 存在「已支付，确认解锁」自证弹窗？ | **不存在** |
| 篡改 paid 位能否伪造已开通？ | **验签失败，拒绝** |
| 篡改金额能否伪造？ | **验签失败，拒绝** |
| 用他人设备密钥能否查到状态？ | **查不到** |
| 未核销的订单会被误判为已支付？ | **不会** |

状态依旧**只由服务端裁决**：支付网关回调或作者后台核销 → 服务端 RSA 私钥签名 → App 内置公钥验签。
客户端只有公钥，私钥永远不在 APK 里。

## 四、用户的完整体验

```
下载安装 → 打开软件 → 点「登录」
    ↓
自动弹出捐赠页（选金额 → 扫码支付，备注填订单号）
    ↓
点「我已支付，申请开通」→ 页面显示「等待确认到账…」
    ↓
作者后台点一次「核销」→ 用户端 3 秒内自动变成「✓ 已解锁」
    ↓
登录成功，全部功能开放
```

**用户全程零配置、零技术术语、零二次点击。**

## 五、作者需要做的一步（只有一步）

```bash
cd 哔小趣-捐赠校验服务
bash 一键部署打包.sh https://你的域名
```

然后：

```bash
ADMIN_TOKEN=你的强口令 node server.js
```

打开 `https://你的域名/admin` → 填管理员令牌 → 核对到账后点「核销」。

> 服务器务必用 HTTPS；私钥 `keys/donate_priv.pem` 请勿外传、勿提交 Git（已加 .gitignore）。

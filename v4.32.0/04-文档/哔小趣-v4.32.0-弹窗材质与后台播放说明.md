# 哔小趣 v4.32.0 · 弹窗材质加深 + 后台播放

> 两个改动：**播放器里的弹窗玻璃压深一档**（透明度调低），**「更多」新增「后台播放」开关**。
> 手机版 / 平板版、原版皮肤 / iOS 皮肤，四个包全部同步。

---

## 一、弹窗透明度调低

之前弹窗和列表卡片共用同一档玻璃 `GlassUtil.card()` —— 深色下主体只有 **24%**。
那档通透度在静态页面上好看，但弹窗是压在**满屏运动、亮度反差极大**的视频上的：
画面亮部整片透上来，菜单文字的黑白对比被冲掉，读起来费劲。

现在给弹窗单独做了一档 `GlassUtil.sheet()`：

| | 改前 card() | 改后 sheet() |
|---|---|---|
| 顶部柔光 | `0x14FFFFFF`（8%） | `0x24FFFFFF`（14%） |
| 主体 | `0x3D2B303B`（**24%**） | `0x7D262B34`（**49%**） |
| 底部收沉 | `0x33212730`（20%） | `0x6E1B2027`（43%） |
| 描边 | `0x14FFFFFF` | `0x1FFFFFFF` |
| 窗外遮罩 | `0.55` | `0.60` |

关键取舍：

- **只动弹窗，不动列表。** 首页卡片、设置页、搜索页那批静态卡片仍然是原来那档通透玻璃 —— 它们在静态底上没有可读性问题，加深反而掉了质感。
- **仍然是玻璃，不是实心块。** 三段渐变的体积感、顶缘一线柔光都保留，只是把"染色浓度"提上去。iOS 皮肤下照旧走 `UiSkin.group()` 的实心分组卡，不受影响。
- 一处改动，全播放器弹窗同时生效：更多 / 清晰度 / 解码方式 / 倍速 / 选集。

对比图：`哔小趣-v4.32.0-弹窗与后台播放.png`（左 24%，右 49%，背后刻意放了一块画面亮部）。

## 二、新增「后台播放」

「更多」菜单里多了一项 **`后台播放：开 / 关`**，默认**关**（保持"退出就停"的旧行为，不会偷偷耗流量）。

### 开启后

- 按 Home、切到微信、锁屏 —— 声音继续，画面回来时接着播。
- 通知栏出现一条常驻通知：`哔小趣 · 正在后台播放`，点它回到播放页，点「停止」直接暂停。
- 从最近任务里划掉 App → 立即停止（不会变成关不掉的后台播放）。
- 回到 App 后通知自动消失，不在前台常驻。

### 关闭后

- 离开 App（整个 App 退到后台）→ 自动暂停；锁屏 → 自动暂停。
- **App 内换页不打断**：首页 → 播放 → 设置 → 返回，这一路进程始终在前台，播放不暂停。
- 因离开而自动暂停的，回到 App 会自动续播；用户自己按的暂停不会被"自动续播"顶掉。

### 为什么要挂一个前台服务

让 `MediaPlayer` 继续跑本身不难，难的是**进程别被回收**。普通后台进程几分钟就可能被系统按 LRU 清掉，声音随之消失 —— 用户感知就是"后台播放没生效"。所以开启时挂一个 `mediaPlayback` 类型的前台服务（`BgPlayService`），把进程优先级顶到"用户可见"。

它**不持有播放器**：播放器、Surface 都还在播放页里，服务只负责顶通知、留住进程。服务与 Activity 同进程，所以通知栏的「停止」走静态回调直接回到主线程，不用广播、不用跨进程。

几个必须踩准的点（都写在代码注释里了）：

| 问题 | 做法 |
|---|---|
| Android 12+ 禁止后台启动前台服务 | 在 **onPause**（本页仍算可见）启动，不在 onStop 启动 |
| Android 14 前台服务必须声明类型 | manifest 里 `foregroundServiceType="mediaPlayback"` + `FOREGROUND_SERVICE_MEDIA_PLAYBACK` 权限 |
| API 26+ 通知必须有渠道 | `NotificationChannel` 反射创建（bootclasspath 是 android-22，没有这个符号） |
| 通知建不起来会导致 FGS 超时崩溃 | `startForeground` 失败即 `stopSelf()`，宁可少保活也不能崩 |
| 区分"退到后台"和"App 内换页" | 查本进程 `importance`，大于 `IMPORTANCE_FOREGROUND` 才算真的到后台 |

### 已知边界

- **DASH 高清模式**（默认，1080P/4K 音视频分离）：音频轨是独立 `MediaPlayer`，后台播放最稳。
- **兼容（合流）模式**（单文件兜底）：声音和画面在同一个 `MediaPlayer` 里，个别机型锁屏销毁 Surface 时可能一起停 —— 这是模式本身的限制，切回默认解码即可。

# 哔小趣 v4.17.0 更新说明

> 版本号：4.17.0（versionCode 116）
> 签名：与 v4.16.1 完全一致（SHA-256 `0930aba7…b67bb148`），可直接覆盖安装，登录态与设置不丢。

本轮目标：**先保证加载速度**，把默认画质降到 720P、图片与视频分级调度、解码改成「优先硬解」，
同时把版面做得更简洁、框框更柔和，并顺手清掉一批重复代码。

---

## 一、首页封面图片加载（本次改动重点）

| 问题 | 旧做法 | v4.17.0 |
|---|---|---|
| 预取挤占可见封面 | 可见封面与预取共用同一个 4 线程池，预取任务把线程占满，用户看到的封面反而迟迟不出 | 拆成两级：**可见封面池**（4 线程，`MAX_PRIORITY`）+ **预取池**（2 线程，`MIN_PRIORITY`），预取绝不抢可见项的 CPU 与带宽 |
| 同一张图重复下载 | 列表快速滑动时同一 URL 会并发发出十几条 HTTP 请求 | 新增 **in-flight 去重**：同一 URL 只下载一次，其余调用方挂回调等同一份结果 |
| 滚动到才加载 | 只在滑到时才开始请求 | 新增 **滚动预取**：滑到时顺手把接下来 8 张封面下好并解码进内存，滑过去零等待出图 |
| 分辨率浪费 | 小缩略图也按大图尺寸下载 | `fit()` 重写：目标宽 × 1.15 为「想要的宽度」——**够用就不换尺寸**（省流量），不够才向上取（上限 1080）；已声明的大图绝不降级重下 |
| 解码尺寸虚高 | 1080 宽的源给 372px 小图用，白占 3 倍内存 | 采样规则改为「解出来的图不超过目标的 1.6 倍」，尺寸最贴合目标 |
| 网络等待过长 | 连接 8s / 读取 12s | 收紧为 **5s / 9s**，失败更快让位给下一条请求 |
| 列表掉帧 | 复用缓存小、滚动时反复重建行 View | `setScrollingCacheEnabled(true)` + 关闭动画缓存，行 View 直接从缓存取 |

## 二、视频加载 · 线路 · 解码

**默认画质改为 720P**

- 旧版默认「自动（最高可用）」，实际会拉到 4K/1080P 高码率流，首帧要 6~10 秒。
- 现在默认 **720P**（存储键换成 `quality_v2`，升级后的老用户也统一从 720P 起步）。
- 需要更高画质时，点播放页顶部「画质」按钮一键切换，**之后的选择会被记住**。

**解码方式：优先硬解（GPU）**

- 新增 `BiliApi.hasHwDecoder()`：用 `MediaCodecList` 区分**硬件解码器**与**软件解码器**
  （API 29+ 走 `isHardwareAccelerated()` 反射，低版本按解码器名前缀判断 `OMX.google.*` / `c2.android.*` 等软解）。
- 旧版 `codecPlayable()` 把软解码器也算作「能解」，于是很多机器实际在**软解 HEVC/AV1** —— CPU 飙高、掉帧、首帧拖成 8 秒，GPU 一直闲着。
- 现在同分辨率有多条轨道时**优先挑有硬解的那条**（分辨率权重远大于此项，不会把 1080P 降成 720P）。
- 解码方式菜单文案同步改为「自动（优先硬解·推荐）」。

**线路：4 条 → 6 条，并新增零成本扩充**

- `BiliApi.videoLines()` / `audioLines()` 上限 4 → 6，并按三级收集：
  1. 同轨道的 `baseUrl` + `backupUrl`；
  2. **同高度、同编码家族**的其他轨道（不同码率版本，也是同一画质的合法来源）；
  3. **主地址换算出的备用 CDN 域名**（`upos-sz-mirrorali / mirrorhw / mirrorcos / mirrorbd`，
     路径与鉴权参数原样保留，纯本地字符串替换、零网络开销，必定是同一份资源）。
- 本地代理 `LocalProxy` 同步支持 `u~u6` 六条候选。
- 竞速错峰 25ms → 16ms（线路变多但竞速总时长不变）；连接超时 5s → 4.5s、读超时 12s → 10s。
- 竞速线程优先级提到 `NORM+1`（选路是起播链路上第一环）。

**播放渲染**

- `TxVideoView`：Surface 由默认的 RGB_565 改为 **RGBX_8888** —— 解码帧省掉一次降位深转换与带宽拷贝，
  GPU 合成压力更均匀、颜色不丢档；同时显式关闭 z-order 抬高（保证弹幕与控件压在画面之上）、播放中不息屏。
- 音频轨与合流播放统一走 `AudioAttributes(USAGE_MEDIA / CONTENT_TYPE_MOVIE)`：音量键、音频焦点、来电暂停都按「影视」处理。

## 三、热搜

- 宽屏搜索页右侧「bilibili 热搜」由 20 条改为 **10 条**（`BiliApi.hotSearch` 里再做一次本地截断，
  保证服务端不按 limit 截断时结果也严格是 10 条）。

## 四、版面：简洁 + 框框更软

| 位置 | 旧 | 新 |
|---|---|---|
| 首页封面圆角 | 9dp | **12dp** |
| 单列列表行圆角 / 缩略图 | 10dp / 7dp | **14dp / 10dp** |
| 封面占位底色 | 刺眼的 `#2a2e36` | 跟随主题的柔和灰蓝（深色 `#242833` / 浅色 `#e9ebf0`），全 App 14 处占位统一 |
| 深色卡片色 | `#1f2229` | `#1e2128`，底色 `#16181d` → `#15171c`，两者对比更小 |
| 卡片间距 / 标题行距 | 8dp / 1dp | **10dp / 2dp** |
| 顶栏搜索胶囊 | 单独写的一套描边渐变 | 复用 `GlassUtil` 玻璃材质，与搜索页输入框、标签胶囊同一套语言 |
| 搜索页右栏 | 热搜 20 条 + 「搜索发现」胶囊区（与左侧「大家都在搜」重复） | 热搜 10 条，每条加圆角玻璃底与按下反馈；**删掉重复的「搜索发现」** |
| 头像 / 封面占位 | 各自硬编码颜色 | 全部收敛到 `ImgLoader.placeholderColor()`，切主题自动跟随 |

## 五、冗余代码清理

- **15 处** `"//" → "https:"` 的重复写法统一收敛到 `ImgLoader.https()`（`PlayActivity` / `MainActivity` /
  `DynamicsActivity` / `DynFeedView` / `UserActivity` / `RelationActivity` / `MsgActivity` / `NovelUtil` / `VideoItem`）。
  顺带修好一批只处理 `"//"`、漏掉 `"http://"` 的老写法。
- 删除 `FeedAdapter.round()`（从未被引用的备用方法）。
- `VideoItem.thumb()` / `thumbHi()` 不再各自实现一遍 https 转换。
- **修复构建脚本**：原 `build.sh` 用 `|| true` 吞掉 javac 报错，编译失败也会产出一个「能装但缺类」的坏 APK；
  现已改为编译报错即中止。

## 六、验证

- `javac`（API22 bootclasspath）全量编译通过，639 个 class。
- `d8 --min-api 22` → `aapt2 link` → `zipalign` → `apksigner`（v1 + v2 + v3）全链路通过。
- APK：`versionCode=116` / `versionName=4.17.0`，签名与 v4.16.1 完全一致，可直接覆盖安装。
- 纯逻辑改动（`fit()` 尺寸换算、`mirrorUrls()` 域名替换、解码采样）已用独立用例逐条验证，16/16 通过。
- dex 内容抽检确认新代码与新文案均已打包。

> 交互层面的手感（起播秒数、滑动帧率）仍需在真机上确认；建议安装后先看首页首屏封面出图速度，
> 以及播放页「画质」按钮切到 1080P 后首帧耗时的变化。

# 哔小趣 v4.15.16 · 二维码渲染失败修复说明

## 一、上一版为什么是一片白框

v4.15.15 的链路是：

```
官方页面（隐藏 WebView）
   → 从 DOM 里取二维码链接（读 img 的 title 属性）
   → 交给 ZXing 本地重画一张码
   → 显示在原生 ImageView 上
```

这条链有 4 个可能断掉的点，任何一个断掉，屏幕就是**白底 + 「二维码渲染失败」**：

1. 选择器 `.login-scan__qrcode img` 没命中（页面结构随时会变）
2. 命中到了元素，但 `title` 上不是 `http` 开头的链接
3. 链接取到了，但 `makeQr()` 编码抛错，返回 `null`
4. 白框是 ImageView 的白底，没图就纯白

你截图里那块大白板，就是第 4 种：ImageView 在，图没来。

## 二、这一版换了思路：不自己画，直接放大官网那张

关键判断：**二维码本来就是官方页面画出来的，为什么要搬出来重画？**

v4.15.16 的做法：

```
可见 WebView（桌面 UA）打开 passport.bilibili.com/login
   → 注入 JS，找到页面里的二维码 <img>/<canvas>
   → 克隆到全屏遮罩里，按屏幕尺寸放大居中
   → 每 1.2 秒把副本的 src 与源元素同步（官方换码，屏幕跟着换）
```

轮询、会话、Cookie 全部由**官方页面自己完成**，我们一个请求都不发。所以：

- 不存在「编码失败」这一环 —— 我们不做编码
- 不存在「链接取错」这一环 —— 我们用的就是屏幕上那张图
- Cookie 天然完整（含 `DedeUserID__ckMd5`、`sid`）

## 三、实测（真实页面，非模拟）

用无头 Chromium 按手机视口（412×820）打开 `passport.bilibili.com/login`，执行注入脚本：

| 检查项 | 结果 |
|---|---|
| 脚本返回值 | `ok:301`（成功挂上遮罩） |
| 遮罩尺寸 | 412×820，铺满可视区 |
| 二维码图片 | 301×301，居中 |
| 白边（静区） | 每边约 26px，满足扫码器要求 |
| 整张截图直接解码 | ✅ `https://account.bilibili.com/h5/account-h5/auth/scan-web?navhide=1&callback=close&qrcode_key=...` |

注意最后一行：**是拿整张截图（含背景、含白卡）直接解码成功的**，不是裁剪后才解出来的。这意味着任何扫码器都能扫到。

## 四、三种情况都能走通

| 情况 | 表现 |
|---|---|
| 正常 | 1~3 秒出现大二维码，扫码 → 手机点「确认登录」→ App 提示「登录成功 ✓ 昵称」 |
| 页面结构变了、取不到二维码元素 | 遮罩不插入，**官方页面本身完整可见**，照样能扫（底部提示「页面二维码未就绪，可点完整页面直接扫」） |
| 页面完全打不开 / 被风控 | 底部三个按钮：`换一张`（重载）、`完整页面`（撤掉遮罩看官网原页面，可切密码/短信）、`短信登录`（独立通道） |

## 五、安装

- 版本：**v4.15.16（versionCode 112）**
- 签名与之前一致（`0930aba7…`），**直接覆盖安装，不用卸载**
- 入口：`我的 → 登录 → 二维码登录`（设置页里的入口同样指向这里）

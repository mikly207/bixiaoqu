# 哔小趣 v4.13.4 更新说明

> 修复：点到其它栏目（动态 / 我的）后再点回「首页 - 推荐」，视频不再整批刷新、不再丢失浏览位置。
> 本版基于 v4.13.3，仅修复首页列表的复用逻辑，其余功能、番剧破解、动态修复全部保留。

## 一、问题现象

在首页「推荐」浏览到某一位置后：

1. 点底部「动态」或「我的」等其它栏目；
2. 再点回「首页 - 推荐」；
3. 视频列表被**重新请求、整批换成新内容**，并且**滚动位置回到顶部**。

这与此前已在 v4.13.3 修好的「动态页串视频」是同一类问题——首页 tab 还没有做视图复用。

## 二、根因

`MainActivity.switchTab(0)`（每次点首页都会走）里写死了：

```java
rows.clear();                        // 清空已有视频
content.addView(newList(...));       // 新建 ListView
loadChannel();                       // 重新发起网络请求
```

所以只要离开首页再回来，就必然清数据 + 重建 + 重新加载一次，表现为"视频刷新了"。

## 三、修复方案

给首页列表加了一套**视图缓存 + 状态复用**机制：

| 改动点 | 说明 |
| --- | --- |
| 新增缓存字段 | `homeRootCache`（列表容器）、`homeRefreshTipCache`（刷新提示）、`homeCacheValid`（是否已有缓存）、`homeScrollPos/homeScrollTop`（滚动位置） |
| `switchTab(0)` 复用分支 | 缓存有效时直接把原列表视图挂回，恢复滚动位置，**不 `rows.clear()`、不新建 ListView、不重新请求** |
| 离开首页前 | 在 `switchTab(idx != 0)` 时记录 `listView` 的滚动位置与首项偏移 |
| `findListView()` | 从缓存容器里找回 ListView，保证复用后引用不丢 |
| `invalidateHomeCache()` | 旋转（`onConfigurationChanged`）、双列开关变化（`onResume`）时作废缓存并重建，避免列数/宽度不符 |

### 仍然会正常刷新的场景（符合预期，未受影响）

- **下拉刷新**：主动下拉仍会拉新一批视频；
- **切换顶部频道**（热门 / 动画 / 影视 / 新番）：走 `loadChannel()` 加载对应频道；
- **旋转屏幕、切换深浅色/双列设置**：布局参数变了，重建视图；
- **主题切换**：Activity 重建，缓存自然失效。

## 四、构建与兼容

- 版本：`v4.13.4`，`versionCode 72`；
- 兼容：`minSdk 22`（Android 5.1）～ Android 17，API22 平台编译 0 错误；
- 签名：与旧版同一证书（`SHA-256 0930aba7…`），可**直接覆盖安装**，无需卸载；
- 签名方案：v1 + v2 + v3 全开；
- dex 校验：已命中 `homeRootCache / homeCacheValid / findListView / invalidateHomeCache / homeScrollPos`。

# 哔小趣 v4.46.1 实验版 · 修复「付了钱却登录不进去」

> **这是 v4.46 引入的 bug，本版已修复。**
> 现象：捐赠页显示「✓ 解锁成功」，但点「登录」仍进不去，被反复弹回捐赠页。

---

## 一、Bug 根因

v4.46 里「是否已开通」有**两套各自独立的判定**，口径不一致：

| 位置 | 判定方式 | 结果 |
|---|---|---|
| 捐赠页 | 宽松模式下写入凭证后**直接显示解锁成功** | 显示「已解锁」 |
| 登录门禁 | 统一走 `isTrusted()` **验签** | 宽松凭证验签必失败 → 判为未捐赠 |

于是产生矛盾：状态显示"已解锁"，实际判定"未解锁" → 点登录又被弹回捐赠页 → **死循环**。

此外还有一个字段顺序错误：宽松凭证被写成

```
v1|relaxed|deviceId||1|amount|method||issued|expires     ← 错：relaxed 落在 deviceId 位
```

而正确格式（与服务端 canonical 一致）应为

```
v1|deviceId|relaxed|1|amount|method|orderId|issued|expires   ← 对：relaxed 在 uid 位
```

导致门禁连"这是宽松凭证"都识别不出来。

---

## 二、本版修了什么

### 1. 判定逻辑收敛为唯一一份

新增 `DonateApi.isUnlocked()` 作为**全局唯一**的判定入口，
捐赠页、登录门禁、状态条全部调用它 —— 从根上消除"显示与判定不一致"的可能。

```
DonateApi.isUnlocked()
   ├── 宽松模式 → 认可宽松凭证（且未过期）
   └── 在线模式 → 必须服务端签名验签通过（安全不降级）
```

### 2. 宽松凭证字段顺序修正

改用 `DonateApi.canonical(...)` 统一构造，`relaxed` 落在 uid 位，与服务端协议完全一致。

### 3. 老用户凭证自动迁移（你当前的情况）

已在 v4.46 付过钱的用户，本地存的是**字段顺序错误的老凭证**。
本版启动时自动识别并迁移成正确格式，**升级后可直接登录，无需重新支付**。

迁移是幂等的，且只针对明确的老宽松格式，服务端凭证与乱码数据都不会被误改。

## 三、你现在要做什么

**只需要装新 APK，不用重新付钱。**

装上 v4.46.1 后：
- 你之前那笔捐赠会被自动识别 → 点「登录」直接进
- 若仍显示未开通，进一次捐赠页点「我已支付，申请开通」即可（宽松模式下会立即写入正确凭证）

| 检查项 | 结果 |
|---|---|
| 在线模式下宽松凭证能否放行？ | **不能**（必须服务端签名） |

| 过期凭证能否放行？ | **不能** |
| 老凭证迁移会不会放过伪造数据？ | **不会**（只认明确的旧宽松格式） |

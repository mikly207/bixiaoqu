> 四件事：**全局主题色（8 色 + 自定义调色）**、**开屏动画重做（中央图标 / 2.69s）**、
> **平板横屏连点推荐的卡顿修复（目标 <0.5s）**、**端口与网络线程调度再调优**。

## 一、全局主题色（非 iOS 版）

设置 → 外观 → **主题颜色**。

- **8 个推荐色**：红 · 橙 · 黄 · 绿 · 青 · 蓝 · 紫 · 粉（默认仍是 B 站粉，老用户观感不变）
- **自定义调色**：色相条（彩虹渐变，可拖动）+ 饱和度 + 明度三条，改一下看一处，**实时生效**
- 顶部有实时预览：色点 / 关注胶囊 / 进度条，不用退出去看效果
- iOS 皮肤下这个入口自动隐藏 —— 那版固定用系统粉（按你的要求只加在非 iOS 版）

### 怎么做到的

旧版强调色是写死的 `#FB7299`，散在 50 多处。这版收成一个单点：

| 位置 | 作用 |
|---|---|
| `Theme.acc()` | 当前主题色 |
| `Theme.c(0x1AFB7299)` | 把「带 alpha 的旧粉色」换成同 alpha 的主题色（50 处全部改走这里） |
| `Theme.a(12)` | 按百分比取半透明主题色 |

换色后不用逐个页面通知：`MainActivity.themeStampOf()` 的指纹里混进了色值，
各页面 `onResume` 发现指纹变了就自己重建 —— 底栏、频道栏、按钮、进度条、
评论抽屉、播放器控件、小说/音乐/消息页全部同步换色。

**游戏厅和跳一跳没跟着换**：那几处的粉色是游戏本身的美术配色（棋子、赛道、道具），
跟着主题变反而会认不出来。

## 二、开屏动画重做

| | 旧版 | 新版 |
|---|---|---|
| 中央 | 空的 | **应用图标**（88dp、22dp 圆角）+ 主题色柔光 |
| 背景 | 整屏插画匀速推近 | 插画 1.00 → 1.05 极慢推近 + 四周径向压暗 |
| 文字 | 底部三行一起淡入 | 图标 → 名称 → 作者 → 标语，间隔 130ms 分层淡入上浮 |
| 收尾 | 140ms 硬淡出 | 230ms 淡出 + 轻微放大 1.02（镜头轻失焦） |
| 时长 | 2.50s | **2.69s**（≤3s） |

柔光不是静态的：先「点亮」（760ms 涨到 95%），再缓缓收到 62%，像一盏灯稳下来。

预览图：`哔小趣-v4.33.0-开屏与主题色.png`（上半是 4 帧时间线）。

## 三、平板横屏连点推荐：卡顿修复

问题不在网络，在于**自己人排队**。旧链路里连点一条推荐会同时发生四件事：

1. 新任务排进 3 条线程的 `PLAY_POOL`，前面被取消的任务还在跑 playurl；
2. 右栏推荐 30ms 后就开始刷新（20 条重新解析 + 重新布局 + 一批封面请求）；
3. 起播海报要等 `play()` 执行到才贴，用户先看到旧画面/黑屏；
4. 旧视频的分片连接还没退完。

这版的四个改动，对着这四条逐一拆：

| 改动 | 效果 |
|---|---|
| **起播票据** `playTicket`：每次点击领号，任务在入口和取址返回后各核对一次 | 被取代的旧任务立刻退出，不再白跑 API、不再堵线程 |
| **PLAY_POOL 3 → 5** | 连点 4~5 下不再排队 |
| **从右栏点进来的不刷新右栏**（`switchVideo(it, true)`） | 省掉一次列表重建，手指还在原位也不会点错 |
| **推荐刷新 30ms → 480ms** | 让「取址 + 首片」先独占链路 |

另外两点：

- **右栏滚动即预热**（`prefetchRecRange`）：停下时把可见区 + 后两条的播放地址取好，
  点哪条基本都是「地址已就绪」——首片只剩 100~200ms 的下载与解码。
- **换片过渡**：海报 190ms 淡入、首帧到达后 320ms 淡出并轻微放大 1.035，
  画面像被「推」出来而不是「揭」开，切视频不再是硬切。

> 说明：0.5 秒是「点击 → 首帧出画」的目标，前提是网络本身正常。
> 地址预热命中 + 线路亲和命中时通常 300~450ms；冷门视频首次取址会多 150~300ms。

## 四、端口与网络线程调度

| 项目 | 旧 | 新 | 原因 |
|---|---|---|---|
| 代理 `ServerSocket` backlog | 128 | **256** | 换片瞬间旧连接未退、新连接涌入，128 个排队位会被打满，多出来的 SYN 被内核丢掉，客户端重试一次就是 1 秒 |
| 代理接收缓冲 | 默认 | **1MB** | 高码率分片一次能装更多，少几次系统调用 |
| 代理 IO 线程 | 6 / 12（队列 96） | **8 / 16（队列 128）** | 稳态是「视频轨 + 音轨 + 前向预读 + 并行段 + 换片残留」，8 条常驻才不排队 |
| HTTP 连接池 | 12 | **16** | 12 条在最忙时刚好卡满，第 13 个请求会把刚握手完的那条挤掉，等于白付一次 TLS |
| 冷启动预热 | 只预热 WBI 指纹 | **再预热 api 长连接 + CDN DNS** | 首页第一次请求省掉 DNS+TCP+TLS 三段（移动网络 150~400ms） |

预热只读 256 字节、**不 disconnect**，连接会回到 keep-alive 池被正式请求复用。

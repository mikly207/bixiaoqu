## 一、弹幕帧率过低 —— 已修复（核心）

### 根因
旧版弹幕位置**完全依赖播放器每 80ms 轮询一次** `setPosition()`，`onDraw()` 又只在位置变化时才延迟重绘。结果：

- 弹幕每秒只走 **约 12 帧**，两次采样之间画面**完全静止**；
- 肉眼可见「一顿一顿」，高分辨率视频上尤其明显。

### 修复方案
重写弹幕层，改为 **Choreographer 逐帧平滑时钟**（跟随屏幕刷新率，通常 60fps）：

| 机制 | 说明 |
|---|---|
| 锚点采样 | `setPosition()` 只记录「媒体位置 + 采样时刻」，不再直接驱动绘制 |
| 逐帧外推 | 每个 vsync 帧用 `锚点 + 速度 × 已流逝时间` 算出平滑位置，帧间不再静止 |
| 速度估算 | 由相邻两次采样推算，指数平滑抑制抖动；**天然兼容倍速播放**（2x 弹幕同步加速） |
| 暂停冻结 | 采样位置不再前进时速度归零，弹幕静止不漂移，省电 |
| 防飞出 | 外推上限 300ms，轮询异常中断也不会把弹幕甩出屏幕 |
| 按需重绘 | 暂停且无新弹幕入场时跳过重绘，降低功耗 |

- 新增纯逻辑类 `DanmakuClock`（外推 / 速度估算 / 边界判定），新增 **14 项单元测试**全部通过；
- 新增 4 条守卫，防止帧率实现被回退；
- `PlayActivity` 侧零改动，接口签名全部保持兼容。

**效果：弹幕从约 12fps 提升到跟随屏幕刷新率（60fps+），滚动连续顺滑。**

## 二、排版问题 —— 已修复

| 问题 | 修复 |
|---|---|
| 网格卡片一行标题忽高忽低，副标题上下错位 | 标题固定预留两行高度，整行副标题对齐、网格底边整齐 |
| 无播放量的视频副标题空掉，导致卡片高度塌陷、行列参差 | 用 `INVISIBLE` 占位替代 `GONE`，行高平稳一致 |
| 单列列表同样因空副标题导致行高跳变 | 同步占位处理 |

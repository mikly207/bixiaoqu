# 哔小趣 v4.17.1 更新说明

> 版本号：versionCode 117 / versionName 4.17.1
> 签名与 v4.16.1、v4.17.0 完全一致，可直接覆盖安装，登录态不丢。

## 本次只解决一件事：退出全屏后视频重新播放

### 根因

问题的源头不在播放器参数，而在**布局树的结构**。

播放页的画面容器 `holder` 里装的是 `SurfaceView`（系统 `VideoView` 内部实现）。
`SurfaceView` 一旦从视图树上被摘下（`removeView`）就会立刻**销毁自己的 Surface**，
系统 `VideoView` 收到 `surfaceDestroyed` 回调后执行 `release(true)` ——**直接把 MediaPlayer 释放掉**；
等它重新挂上去时，`surfaceCreated` 又调用 `openVideo()`，用同一个地址**从头 prepare**。

旧版的分屏逻辑正是这么写的：

```java
root.removeView(holder);                 // ← Surface 在这里被销毁
splitLeft.addView(holder);               // ← 重新挂上，播放器从头开始
```

于是所有会经过分屏的路径都表现为「视频重新播放」：

- 横屏分屏状态下点全屏（进入全屏前要先退出分屏）
- 全屏退出时设备仍是横屏（平板横放、或全屏前就是横屏）→ 自动回到分屏
- 手机上退出全屏时若设备没转回竖屏 → 同样回到分屏

另外退出全屏后固定延迟 520ms 才恢复到分屏，这段时间里播放页处于「视频没了、详情也没了」的中间态，
观感上更像「重新加载了一次」。

### 修法

**一、画面容器全程不搬家**

分屏只搬「不含 Surface 的控件」：控制条浮到画面底部，简介与推荐列表进右栏；
`holder` 始终是 `root` 的第 0 个子视图，切换时只改它的尺寸参数（`LayoutParams`），
`Surface` 从头到尾没被销毁过 —— 播放器、缓冲、解码器全部原地保留，退出全屏画面直接接着走。

顺带清掉了左栏那个只为搬家而存在的 `splitLeft` 容器。

**二、控制条搬移改成幂等**

以前从分屏直接进全屏时，控制条已经在浮层里，旧写法又 `addView` 了一次 ——
同一个 child 二次挂到同一父容器在 Android 上是直接抛 `IllegalStateException` 的。
现在统一走 `ctrlToOverlay()` / `ctrlToRootFlow()`，先判断父容器再动，
这条最快能复现崩溃的路径已经被堵住。

**三、退出全屏的恢复时序按「会不会旋转」分开处理**

- 当前已是横屏（不会发生旋转）→ 60ms 后直接回分屏，不再干等 520ms，中间态基本看不到
- 当前是竖屏（真的要转）→ 仍等 450/520ms 让旋转动画走完，且**先确认方向真的变了**再进竖屏铺满或分屏，
  避免平板横放时误触发竖屏铺满

**四、全屏按钮加 350ms 节流**

旋转要 300~600ms，这期间连点会让两次方向请求互相打断，布局停在「刚退出又进全屏」的中间态。
现在 350ms 内的第二次点击直接忽略，只认第一次。

**五、兜底：万一 Surface 还是被重建，也不能从 0 秒开始**

`TxVideoView` 新增 `OnSurfaceLost`：窗口/容器即将分离前，把真实播放进度和播放状态交出来，
上层写回 `resumePos` —— 重建后从断点 `seekTo` 接续，暂停态也会保持，不会自己播起来。
正常情况下这条路径根本不会触发（第一项已经根治），纯粹是给系统回收、厂商定制这类意外留的保险。

## 建议验收路径

1. 横屏分屏看视频 → 点全屏 → 再点退出：画面应无中断、进度连续
2. 平板横放：竖屏播放 → 全屏 → 退出：应直接回分屏，不闪白、不重播
3. 手机竖持：全屏 → 退出：转回竖屏详情页，进度连续
4. 快速连点全屏按钮 5~6 次：不应出现布局错乱
5. 播放到中途暂停 → 全屏 → 退出：仍应保持暂停，不自动播放

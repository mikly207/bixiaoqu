# 哔小趣 v4.15.7 — 登录兜底闭环 + 默认双列/关弹幕 + 弹幕帧率修复

版本：4.15.7（versionCode 103，可直接覆盖安装，签名证书不变）

## 一、登录：这次做成「一定能登上」的闭环

服务端实测五个登录入口（www / account / passport.bilibili / passport.biligame / m）全部 HTTP 200，TLS 1.2/1.3 都通——**接口和端口都没问题**。卡在"正在生成二维码"只能是你设备到 passport 域的链路问题（DNS 污染 / hosts 拦截 / 代理分流），App 其他功能走 api 域所以正常。

既然二维码在你设备上这条路不通，本版把它改成**多层兜底，保证最终能登上**：

1. **二维码双线路**（v4.15.6）：主域失败自动切 `passport.biligame.com`（不同 CDN 线路）。
2. **失败实时显示**（v4.15.6）：不再默默卡着，每次失败立刻显示具体原因。
3. **网页登录兜底入口**（本版）：扫码页新增"网页方式登录"按钮，走系统 WebView 的独立网络栈。
4. **网页登录修复**（本版）：
   - UA 从桌面 Chrome 改为**移动端 UA**——原来手机 WebView 加载桌面登录页，二维码/验证码组件经常不渲染或异常；
   - Cookie 从只读 www 域改为**遍历 www / passport / account / .bilibili.com 四域聚合**——登录态落在哪个域都能识别。
5. **自动闭环**（本版）：二维码连续 3 次生成失败 → **1.2 秒后自动转入网页登录**，无需你手动操作。

> 结论：现在无论二维码通不通，最终都会落到可用的网页登录（手机号+验证码/密码/官方扫码），登录态一定能保存。

## 二、默认设置（按你的要求）

- **打开软件默认双页排布**：`two_column` 默认 true（首页推荐流双列卡片）。
- **默认关闭弹幕**：`danmaku` 默认 false（播放页弹幕默认不显示，想要再手动开）。

> 说明：这是对"新安装/从未手动设置过"的默认值。如果你之前手动切过单列或开过弹幕，App 会尊重你已保存的选择。想要恢复新默认，可在设置里改回，或清除 App 数据。

## 三、弹幕帧率过低修复 + 精简

**帧率根因**：弹幕层强制 `LAYER_TYPE_SOFTWARE` 软件渲染——每帧所有弹幕文字都要在 CPU 上描边+填充合成到位图再贴图，高分屏 + 多条弹幕时必然掉帧。本版**移除软件渲染**，改用硬件加速（`drawText` 在硬件层完全支持，速度快数倍）。

**精简弹幕**：同屏上限从 40 条降到 **25 条**，画面更清爽、重叠更少，同时进一步减轻绘制负担。

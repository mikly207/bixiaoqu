# 哔小趣 v4.15.13 —— 扫码登录：这次不是换顺序，是换网络栈

**版本**：v4.15.13（versionCode 109）
**兼容**：Android 5.1（API 22）及以上
**签名**：不变（`0930aba7…`），覆盖安装

---

## 一、先说清前两版为什么没解决

| 版本 | 做法 | 结果 |
| --- | --- | --- |
| v4.15.11 | 直连不通 → 云端兜底 | 卡 42s：云端排在最后，轮不到 |
| v4.15.12 | 云端优先 → 直连兜底 | 卡 18s：云端在**你手机上**也不回，然后才轮到直连 |
| **v4.15.13** | **修底层 + 换网络栈** | 三路并行 6 秒内出结果，浏览器通道兜底 |

前两版都在「调整请求的先后顺序」，但问题不在顺序 —— 是**同一台手机上，App 的 HTTP 请求发不出去，而浏览器的请求能发出去**。这是两层不同的网络实现，顺序怎么排都没用。

三个具体病灶，这次逐个拆：

| 病灶 | 现象 | 本次修复 |
| --- | --- | --- |
| **TLS 协商** | 老系统 `HttpsURLConnection` 默认只谈 TLS 1.0/1.1，passport 与云端 CDN 只收 1.2 → 握手挂起，不报错只等待 | 每个 HTTPS 连接显式挂 **TLS 1.2** socket 工厂 |
| **IPv6 黑洞** | 先解析到 AAAA 地址，连不通也不立刻失败，整条链路卡在握手前 | `preferIPv4Stack=true`，强制走 IPv4 |
| **串行排队** | 一条挂起，后面全等着 | **三路并行竞速**（云端 / passport 主域 / passport 备域），先成功的先用，6 秒总窗口 |

## 二、新东西：浏览器通道（关键）

既然你手机上的**浏览器能打开网页、App 的 HTTP 发不出去**，那就别用 App 的 HTTP 栈了。

新增 `QrBridgeActivity`：一个隐藏的 WebView 直接去请求云端二维码接口，把返回的 JSON 文本读回来，再在原生层渲染二维码。扫码、轮询、取凭据全走这条链路 —— **和你在浏览器里打开网页是同一套网络栈**。

已经用无头 Chromium 实测过这条路径（接口返回 `code:0` + `qrcode_key`，页面文本可正常读取）。

顺带加了一层：`完整 Cookie` 保存（`DedeUserID__ckMd5` / `sid` 全在），官方网页登录那条路也一样，重启 App 不会再退回「未登录」。

## 三、你现在的操作流程

1. 覆盖安装 `哔小趣-v4.15.13.apk`；
2. `我的 → 登录 → 二维码登录`；
3. 三种可能，都会自动走：
   - **6 秒内出码** → 直接扫（TLS/IPv4 修好后的正常情况）；
   - 6 秒没出来 → 自动切**浏览器通道**（再 1~2 秒出码）；
   - 浏览器通道也失败 → 页面会明说「浏览器通道也失败：原因」，下面有「改用官方网页登录」。
4. 扫码 → 手机点确认 → App 提示「登录成功 ✓ 昵称」。

失败时页面会显示三路诊断，例如 `云端✗6000ms · bilibili✗4000ms · biligame✓800ms`。**如果还失败，请把这行诊断截图给我** —— 它直接告诉我哪条通、卡在哪个环节，不用再猜。

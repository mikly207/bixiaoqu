# 哔小趣 v4.7 · 点相关推荐"获取播放地址失败：啥都木有"修复说明

> 版本：v4.7（versionCode 47 / versionName 4.7）
> 日期：2026-11-24
> 基线：v4.6（音画同步修复）

---

## 一、现象

在播放页底部的「相关推荐 · 点即切换」里点任意视频，画面黑掉并提示：

```
播放失败：获取播放地址失败：啥都木有
```

同一个视频如果从首页/搜索点进去则播放正常。

---

## 二、"啥都木有"是什么

这四个字**不是本 App 的文案**，是 B 站服务端返回的 `message`。对应 `code = -404`，含义是「请求的这个视频/分P不存在」。

更准确地说：**`bvid` 和 `cid` 不匹配**。B 站有两条独立标识：

| 字段 | 含义 | 是否唯一指向一个视频 |
|---|---|---|
| `bvid`（如 BV1xx411c7mD） | 稿件号 | 是（一个稿件） |
| `cid` | 分P/流编号 | **否**，只在稿件内唯一 |

`playurl` 必须同时带 `bvid` 和 `cid` 且**两者属于同一个稿件**。带上别的稿件的 cid，服务端就回 `-404 啥都木有`。

---

## 三、根因（代码级）

### 1. 列表页会通过 Intent 预传 cid（本意是提速）

```java
// PlayActivity.onCreate
prefetchedCid = getIntent().getLongExtra("cid", 0);     // 列表页传来的 cid
```

### 2. play() 无条件优先复用这个 cid

```java
// 修复前的 play()
if (bv != null && prefetchedCid > 0 && pageIndex == 0) {
    cid = prefetchedCid;      // ← 直接用，不核对它属于哪个稿件
    realBvid = bv;
    ...
}
```

### 3. 但 switchVideo() 只改了 bvid，没清 cid

```java
// 修复前
void switchVideo(String bv) {
    bvid = bv;        // 换了稿件号
    ...               // prefetchedCid 原封不动！
    play(...);        // 于是 play() 拼出 bvid=新稿件 & cid=旧稿件
}
```

拼出来的请求是：

```
GET /x/player/playurl?bvid=新视频的BV&cid=上一个视频的cid
```

服务端判定 cid 不属于该稿件 → `-404 啥都木有`。

**这也解释了为什么只有"相关推荐"会失败**：
- 从首页/搜索进入 → 新建 Activity，`prefetchedCid` 与该视频一致 → 正常
- 页内点推荐 → 同一个 Activity 内换视频，`prefetchedCid` 是**上一个视频的** → 必失败

---

## 四、修复内容

### 1. 切视频时清空全部「上一视频的残留状态」

```java
void switchVideo(String bv) {
    bvid = bv;
    prefetchedCid = 0;        // ★ 根因修复：不再复用旧 cid，改走 pages() 现查
    prefetchedTitle = "";
    prefetchedDur = 0;
    prefetchedAspect = 0f;
    pageIndex = 0;            // 新视频从第 1P 开始
    pagesArr = null;          // 丢弃上个视频的分P列表
    resumePos = 0;            // 否则会沿用上个视频的播放进度
    pendingResumeMs = 0;
    dashFailed = false;       // 上个视频 DASH 失败不能连累新视频
    playDataCache = null;
    pageDurMs = 0;            // 进度条别显示成上个视频的时长
    ...
}
```

> 除 cid 外，`resumePos`、`dashFailed`、`pageIndex` 三个残留状态也都会造成串台问题，一并清掉。

### 2. 补回"切清晰度不必多一次请求"的优化

`prefetchedCid` 清零后，切清晰度会白跑一次 `pages()`。用当前已缓存的 `curCid` 补位：

```java
long knownCid = prefetchedCid;
if (knownCid <= 0 && snapCid > 0 && pageIndex == 0 && bv.equals(snapBv)) {
    knownCid = snapCid;       // 仍是同一个视频 → 复用已取到的 cid，零网络开销
}
```

同时把 `curCid / curBv / videoTitle / pageDurMs` 在 UI 线程快照后传入工作线程，避免读到半更新状态。

### 3. 连点推荐不再"串台"（竞态修复）

快速连点两个推荐会并发启动两条 `play()` 线程，**旧视频的结果晚返回会把新视频覆盖回去**。三处回调统一加校验：

```java
ui.post(() -> {
    if (!bvF.equals(bvid)) return;   // 已经切走了，丢弃这次结果
    ...
});
```

同样给 `loadVideoMeta` 加了 `if (!bv.equals(bvid)) return;`，防止旧视频的标题/UP主/点赞状态盖掉新视频。

### 4. 错误文案翻译成人话

B 站的 `-404 啥都木有`、`87007` 这类码对用户毫无信息量。新增 `playErrText()`：

| 服务端返回 | 现在显示 |
|---|---|
| `-404 啥都木有` | 该视频不存在或已失效 |
| `-403` | 该视频已下架或无播放权限 |
| `-10403` | 该视频需要大会员账号 |
| `87007` | 这是充电专属视频，需先充电 |
| `87008` | 这是付费课程视频 |
| `-101` | 请先登录后再播放 |
| `-412` | 请求被风控拦截，请稍后重试 |

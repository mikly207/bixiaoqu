# 哔小趣 v4.13.16 更新说明

修复两类问题：**横竖屏旋转后比例错乱** + **历史记录封面不加载**。

## 一、修复历史记录封面全是灰块

**根因**：`History.add()` 从头到尾只保存了 bvid / 标题 / 观看时间，**封面地址根本没写进本地存储**；`History.list()` 构造列表项时 `pic` 直接传 `null`，适配器拿到空地址自然只显示灰色占位块。

**修复**：
1. 本地记录新增 `pic` 字段并持久化（写历史时把封面 URL 一起存下）。
2. 播放页在 meta 请求拿到真实封面后，带封面重新写入历史（去重置顶，不重复堆积）。
3. 已存在的旧记录：下次再观看同一视频时，会自动把封面补齐。
4. 历史列表读取时把 `pic` 带出，缩略图正常显示。

## 二、修复旋转/转正后比例错乱（拉伸、细长条、大黑边）

**根因**（v4.13.15 旋转功能的三处缺陷）：
1. **旋转几何算反**：横屏视频旋转分支在竖屏持机（`screenAr < 1/宽高比`）时把容器宽高设反，容器比例变成 `1/宽高比`，播放器内部按此 letterbox 后画面被拉伸、裁成细条。
2. **异步竞态**：`applyPortraitFillSize()` 用 `post` 延迟执行，到时候才去读"当前"的宽高比——快速滑动切视频时会读到下一条的比例，导致画面和下一条数据错配。
3. **切视频沿用旧比例**：目标条目没带 `aspect` 时，沿用上一条的横屏比例，把竖屏视频当成横屏去旋转 → 中间一条细长画面 + 两边全黑。

**修复**：
1. **重写排布算法**：容器比例始终等于视频真实宽高比（播放器内部零 letterbox）；横屏旋转时按 `vh = max(屏宽, 屏高/宽高比)`、`vw = vh × 宽高比` 计算，旋转 -90° 后正好 cover 整个竖屏，不拉伸、不留黑边。竖屏视频保持比例 cover、左右略裁切。横屏"转正"态按宽度完整显示。
2. **捕获参数快照**：进入排布当刻就把 `宽高比 / 是否竖屏 / 是否旋转` 存进快照传给布局线程，不再延迟读易变的成员变量，杜绝切视频串比例。
3. **切视频逐条刷新比例**：目标没有 `aspect` 就重置为中性值，绝不沿用上一条；切视频同时清零缩放与旋转残留。
4. **旋转阈值统一**：判断、排布、"转正/旋转"按钮三处统一用同一阈值，避免"按钮显示可旋转但画面没转"的错位。
5. **复位彻底**：退出铺满 / 切竖屏视频时，rotation、pivot 一律复位，不污染下一条。

## 兼容性
- 内核未改动，仍为系统 VideoView。
- 横屏旋转铺满仍需 Android 7.0+；5.1/6.0 自动降级为普通显示，不影响播放、不黑屏。
- v4.13.9 起的 403 竞速修复、线路亲和、边看边预热等网络/播放优化全部保留。

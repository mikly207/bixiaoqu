# 哔小趣 v4.45.0 实验版 · 捐赠状态服务端校验（安全修复）

> **本版修复了一个恶性漏洞**：此前在捐赠页点「已支付，确认解锁」即可直接获得捐赠身份，
> 属于前端自证，任何人点一下都能解锁、且本地缓存可随意篡改。本版把裁决权彻底移到服务端。

---

## 一、问题与修复对照

| | v4.44（有问题） | v4.45（当前） |
|---|---|---|
| 状态来源 | 本地布尔值 `Prefs.donated` | 服务端下发 + **RSA-SHA256 签名凭证** |
| 点「已支付」 | 直接写本地 → 立刻"解锁" | 只向服务端查询；**服务器说没付就是没付** |
| 篡改本地缓存 | 能，改完即生效 | **不能**，验签失败即判为未捐赠 |
| 每次登录 | 只读本地缓存 | **在线向服务端拉取并验签** |
| 私钥位置 | —— | 只在服务端，App 内**只有公钥** |
| 支付确认 | 用户自己说付了 | 服务端核销（网关回调 / 后台人工核销） |

### 已删除的前端自证路径

- `Prefs.setDonated()` —— **已彻底移除**（App 内不存在任何置成功方法）
- `Prefs.donated()` 本地布尔开关 —— **已移除**
- 捐赠页「已支付，确认解锁」二次确认弹窗 —— **已删除**
- 捐赠页按钮改为 **「刷新支付状态」**，只查询、不写状态

> 守卫脚本已加入 **12 项 v4.45 负向断言**，防止此漏洞被重新引入。

## 二、现在的捐赠流程

```
用户选金额 → 点「刷新支付状态」
      ↓
App 向服务端创建订单，拿到订单号
      ↓
用户扫码转账（备注填订单号，便于后台核对）
      ↓
你在微信/支付宝账单核对到账 → 后台点「核销」
   （或接入官方商户，走支付网关自动回调）
      ↓
用户再点「刷新支付状态」→ 服务端返回已支付（带 RSA 签名）
      ↓
App 验签通过 → 显示「服务端已确认，登录已解锁」
```

**关键**：用户在 App 里无论怎么点，都无法自己把状态改成「已支付」。

### 登录门禁

每次触发登录都会**先向服务端拉取状态并验签**：

- 服务端确认已支付 → 放行登录
- 服务端确认未支付 → 引导去捐赠页
- 服务端不可达 → 仅当本地存在**未过期且验签通过**的服务端凭证才放行，否则明确拒绝并提示重试
- 未配置服务端 → 拒绝并引导去设置（不静默放行）

登录成功后自动把设备与 B 站账号在服务端绑定，换设备登录也能识别。

## 四、使用前必读

**这是必要的一步**：不部署服务端，App 无法确认捐赠状态，登录会被拦住。

1. 部署服务端（详见 `哔小趣-捐赠校验服务/README.md`）：
   ```bash
   cd 哔小趣-捐赠校验服务
   ADMIN_TOKEN=你的强随机令牌 node server.js
   ```
2. App → 设置 → 捐赠校验服务 → 填**服务地址**与**校验公钥**
   （公钥取 `keys/donate_pub.hex` 或 `GET /api/pubkey`）
3. 打开服务端 `/admin`，填管理员令牌，即可看到订单并点「核销」

> 静态个人收款码没有自动回调，所以到账需要你在后台核销一次。
> 若已接入微信/支付宝官方商户，把异步通知指向 `/api/pay/notify` 即可自动核销。

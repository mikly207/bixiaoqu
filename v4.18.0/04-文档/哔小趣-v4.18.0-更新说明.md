## 一、横屏右栏点视频：黑屏卡死（有声音没画面）

### 根因（三条叠加）

1. **旧解码器没交还**。换片时旧版只调 `pause()`，旧 `MediaPlayer` 仍占着硬件解码器实例。
   部分机型两个硬件解码器并存时，新的那路 `onPrepared` 正常回调、音频正常，
   但画面永远不出——正是「有声音、一片黑」。
2. **上一路的连接还在抢带宽**。切走后旧视频的音轨、分片下载仍在跑，
   占着 socket 和读线程，新视频的竞速请求只能排队，表现为长时间停在 `00:00`。
3. **旧播放器的报错会反噬新视频**。旧连接断开后旧播放器报 error，
   它挂的还是上一个视频的 `onError` → 触发 `fallbackMux` → 重新取址 → 把刚切过去的新视频打断。

### 修法

- `TxVideoView.reset()`：`stopPlayback()` + 反射调用 `suspend()`（API 24+），
  把解码会话彻底交还系统，Surface 保留复用。在**新地址就绪那一瞬**调用，
  旧画面保留到最后一刻，黑屏时间最短。
- `silenceOldPlayer()`：换片/切档前先把旧播放器的 `onError` 换成一个静默吞掉的回调，
  旧连接被掐断时安静退出，不再打断新播放。
- 代理层「代际取消」（见第三节）：换片瞬间断开上一代所有在途连接，新视频独占带宽。
- 选流增加**软解惩罚**：1080P 以上若本机只能软解，直接压到硬解的中分辨率之后。
  4K 走软解必然掉帧、甚至首帧永远出不来，宁可给硬解的 1080P。
- 分屏画面尺寸改为**跟随容器布局变化重算**（`addOnLayoutChangeListener`），
  修掉「竖屏视频缩成角落一条小竖条」——旧版只在换视频时算一次，那时容器还没测量完，
  新视频沿用了上一条的尺寸。

## 二、切清晰度：慢、不同步、重复播放

### 根因（三条叠加）

1. 旧版每次都**重新请求 playurl**，光取址 0.3~1 秒；
2. 旧音轨没停，那 1 秒里旧声音还在放，之后新音轨再起一遍 → 听起来就是「重复播放」；
3. 合流模式下 `resumePos = dashMode ? 位置 : 0` —— 合流时位置被清零，切完**从头播**。

### 修法

- **本地重选，零网络请求**：playurl 一律按「最高可用」请求，
  一份数据里已经含 4K/2K/1080/720 全部轨道。切档时直接 `pickVideo()` 重新挑一条，
  不再发网络请求。这是「切档瞬间完成」的关键。
- 切档前：旧音轨立刻静音并 `release()`，旧画面继续停在原处（不黑屏）。
- 记录真实进度与播放状态：新的一路 `seekTo` 回原位；原本暂停的，切完仍保持暂停，不会自己播起来。
- 全程只有一个解码器：新流打开前先 `reset()`，不存在两路并存。
- 缓存里没有该档（如 4K 需大会员）时才回落重新取址，并有 toast 说明实际使用的档位。

## 三、线程与网络优先级

| 环节 | 改动 |
|---|---|
| **代际取消** | 每次换片/换档 `newEpoch()`，立刻 `disconnect()` 上一代登记的所有连接；旧代请求到达代理直接拒掉。 |
| **连接线程池** | 旧版每个连接 `new Thread()`（快速换片时线程数翻几倍）→ 固定池 4~8 线程 + 48 队列，超出直接拒。 |
| **起播线程池** | 每次 `play()` 起一条线程 → 固定 3 线程池（`bxq-play`，优先级 NORM+2）。 |
| **视频优先** | 音轨不再和视频轨并行抢带宽：视频 `onPrepared` 后延迟 60ms 才拉音轨。画面先出，体感快得多。 |
| **推荐预热** | 推荐列表出来后 700ms，预热前 3 条的 playurl（只请求地址，不拉视频数据），点下去直接命中缓存。 |
| **统一缓存键** | 所有预取入口（首页、相邻、推荐）统一用 `BiliApi.QN_ALL`，否则和播放时的 key 对不上，预取等于白做。 |
| **起播打点** | 每次起播写一行 `perf … 首帧 xxxms`，可直接核对 2 秒目标、判断慢在取址还是解码器初始化。 |

## 四、两个版本

| | 平板版 | 手机版 |
|---|---|---|
| 横屏播放 | 视频 + 右栏详情/推荐（分屏） | 直接全屏 |
| 首页网格 | 按屏宽 2~4 列自适应 | 固定 2 列（或用户选单列） |
| 搜索页 | 宽屏右侧 1/3 热搜栏 | 单栏，不出右栏 |
| 动态页 | 宽屏头像栏更宽 | 固定窄栏 |
| 代码量 | 649 个 class | 641 个 class（无分屏 / 宽屏热搜代码） |

手机版是**真实裁剪**，不是开关：`enterSplitMode/exitSplitMode/applySplitSize`、
`splitMode/splitRight`、宽屏热搜栏整套（`buildHotPanel/loadHot/renderHot`）都已删除，
class 少 8 个、dex 小 5.8KB。

## 六、建议验收

1. 横屏分屏 → 右栏连点 5 个不同推荐（含竖屏视频）：每个都应正常出画，
   竖屏视频应居中显示而不是细条，且没有「有声音没画面」。
2. 播放中切 720P → 1080P → 720P：应无明显黑屏、进度不跳回 0、不出现两路声音。
3. 暂停状态下切清晰度：切完应仍是暂停。
4. 关注日志里的 `perf` 行：正常网络下首帧应 ≤ 2 秒。
5. 手机版：横屏应直接全屏，不应出现双栏。

若仍有个别视频卡住，请把日志里 `perf` 与 `proxy` 两类记录发我，能直接定位是取址慢、
某条线路不通，还是该编码在本机确实没有可用解码器。

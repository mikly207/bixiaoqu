# 哔小趣 v4.15.9 更新说明

**版本**：v4.15.9（versionCode 105）
**兼容**：Android 5.1（API 22）及以上
**签名**：证书不变（SHA-256 前缀 `0930aba7…`），可直接覆盖安装

## 本次内容

**扫码登录回归**，并把网页版排查出的问题一并修掉。

### 1. 登录方式弹窗恢复「二维码登录」

`我的 → 登录`（或顶栏登录入口）现在提供两个选项：
- **二维码登录**（默认主按钮）：B 站手机 App 扫码确认
- **验证码登录**：B 站官方网页，手机号 + 短信验证码

### 2. 修复扫码被风控拦截：Origin 按目标域下发

`BiliApi` 此前对所有请求都写死 `Origin: https://www.bilibili.com`，
但扫码接口在 `passport.bilibili.com` / `passport.biligame.com` 域，
来源域不一致容易被风控拦下（表现为二维码一直生成不出来）。
现在按请求 host 自动设置 Origin，passport 域用 `https://passport.<域名>`。

### 3. 补齐设备指纹 `_uuid`

B 站会比对设备 ID。生成二维码、轮询、后续接口若指纹不一致，
会出现「认得出账号、但不认可会话」（nav 返回 `isLogin=false`）。
现在 `_uuid` 缺失时按 B 站同构格式生成并全程复用。

### 4. 凭据提取改为「原值优先」

顺序调整为：**Set-Cookie 原值 → data.url 原样参数 → URL 解码参数**。
旧版优先用解码值，`SESSDATA` 里的 `%2C` 被还原成逗号后可能不被认可。

### 5. 保存完整登录 Cookie，不再只存三件套

新增 `BiliApi.exportLoginCookie()`，把 `SESSDATA / bili_jct / DedeUserID /
DedeUserID__ckMd5 / sid` 一起持久化到 `full_cookie`，启动时经 `addCookie()` 恢复。
同时修复 `addCookie()` 只按第一个 `=` 切分、会把后续字段全塞进 value 的解析缺陷。

### 6. 扫码成功后实测登录态

确认后调用 `navInfo()` 校验（读取 **`data.isLogin`**，B 站登录态在 data 节点内），
会话生效有延迟时最多重试 4 次；成功则提示「登录成功 ✓ 昵称」并关闭页面。

### 保留的既有能力

- 双域兜底（passport.bilibili.com / passport.biligame.com）
- 二维码过期自动换新、轮询代次隔离（旧线程不污染新码）
- 三次生成失败自动转入 WebView 网页登录兜底

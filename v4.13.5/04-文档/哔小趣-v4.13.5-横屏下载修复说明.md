# 哔小趣 v4.13.5 更新说明

> 修复：横屏视频有概率下载不出来 / 加载缓慢的问题。
> 本版基于 v4.13.4，只改下载与加载链路，界面、番剧破解、动态修复、首页推荐不刷新等功能全部保留。

## 一、问题成因

横屏视频多为 DASH 高清双流（1080P / 2K / 4K，画面 + 音轨分离），数据量远大于竖屏短视频。排查发现两类问题叠加：

1. **v4.13.x 分支丢失了 v4.14 曾验证过的下载优化**：当前分支没有 `TCP_NODELAY`、转发并发闸门、带宽预估/回填、预取闸门、选流带宽预算。这些正是之前为"高码率不卡、不断连"做的设计，缺失后横屏高清流更容易下载失败或加载缓慢。

2. **线路竞速只取首包、断流无补救**：`LocalProxy` 并行竞速多条 CDN 线路，谁先返回响应头就用谁。但"响应头快"不等于"整段传输稳"。一旦胜出线路在**传输中途断流**，`read()` 提前结束，客户端收到的字节少于声明的 `Content-Length`，MediaPlayer 判定数据不全 → 播放失败 / 下载不出来。而此时备用线路已被释放，无法补救——这正是"**有概率**"的来源（取决于随机竞速到哪条线路）。

## 二、修复内容

### 1. 合回 v4.14 已验证的下载优化（BiliApi / LocalProxy）

| 优化 | 作用 |
| --- | --- |
| 带宽预估 `estBandwidthBps` + 实测回填 `noteThroughput` | 播放中由代理回填真实带宽，等效于播放器的 BandwidthMeter |
| 选流带宽预算（`bwRank`） | 同档画质内优先选链路扛得住的码率，避免"同是 1080P 却选了超高码率"导致卡顿 |
| 预取并发闸门 `PREFETCH_GATE(2)` | 同时最多 2 个预取在飞，避免接口堆积/风控 |
| 转发并发闸门 `chunkGate(2)` | 同时最多 2 个分片转发，避免 CDN 带 token 直链因请求堆积过期 |
| `TCP_NODELAY` | 首块立刻下发，缩短起播缓冲等待 |

### 2. 新增：断流自动断点续传（LocalProxy，核心）

- 竞速胜出线路传输中途断开且未读满 `Content-Length` 时，自动改用**备用线路**按绝对偏移 `Range: bytes=<起点+已读>-` 续传；
- 响应头只发一次，续传数据直接续写，**对播放器完全透明**；
- 每条备用线路最多尝试一次，有限次重试，不死循环。

### 3. 新增：缓存下载断点续传重试（PlayActivity）

- "缓存 MP4"的 `download()` 加入最多 3 次重试，断流后按 `Range: bytes=<已写>-` 续写到同一文件；
- 缓冲区 64KB → 256KB，收紧超时以更快触发重试；
- 服务端不支持 Range（返回 200）时自动从头覆盖重置，避免文件错乱。

## 三、构建与兼容

- 版本：`v4.13.5`，`versionCode 73`；
- 兼容：`minSdk 22`（Android 5.1）～ Android 17，API22 平台编译 0 错误（498 个 class）；
- 新增 API 均为低版本可用（`java.util.concurrent.Semaphore`、`HttpURLConnection.setRequestProperty` 等）；
- 签名：与旧版同一证书（`SHA-256 0930aba7…`），可**直接覆盖安装**，v1+v2+v3 签名全开；
- dex 校验：命中 `chunkGate / estBandwidthBps / noteThroughput / PREFETCH_GATE` 及"断流续传"等日志字符串。

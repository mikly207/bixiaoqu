> 本版针对你反馈的三件事：**五个交互图标重绘（更高级饱满、浅色模式可读）**、**评论可点赞**、**进一步优化代码与流畅度**。

## 一、五个交互图标重绘

### 改了什么

| 图标 | 旧版 | 新版 |
|---|---|---|
| **点赞** | 细线描边 + 镂空，视觉发飘 | **实心拇指**，面块铺满 24×24 视觉框 |
| **评论** | 细线气泡 + 细横线 | **实心气泡 + 三条镂空横线**，对比更强 |
| **投币** | 细圆环 + 细 ¥ | **实心硬币 + evenOdd 镂空 ¥**，厚重有分量 |
| **收藏** | 细线空心星（描边约 1.3） | **内星向中心收 15%，描边加粗到约 2**；选中态纯实心星 |
| **转发** | 镜像填充箭头，线条偏细 | **2.6 粗圆头描边弯箭头 + 圆角箭头尖**，饱满圆润 |

设计原则：

- **面块优先**：能用实心面表达的就不要用细线，远看也有存在感。
- **镂空做层次**：投币的 ¥、收藏的内星、评论的横线全部用 `evenOdd` 挖空，实心里透出背景，比叠色更高级。
- **统一视觉框**：五个图标仍然共用 24×24 viewport 与 24dp 尺寸，放大缩小不会有的大有的小。
- **tint 全部生效**：`Ic.view()` 的 `setColorFilter()` 对填充和描边一视同仁，所以选中态换色、浅色模式换色都正常。

## 二、浅色模式下图标看不清（根因修复）

### 根因

图标资源本身是白色的（`fillColor="#FFFFFFFF"`），靠外部 `setColorFilter()` 着色。
问题出在 `PlayActivity` 的 `makeAct()` / `styleAct()`：

```java
a.icon = Ic.view(this, off, Color.WHITE, sizeDp);
a.icon.setColorFilter(on ? onColor : Color.WHITE);
```

**未选中态写死 `Color.WHITE`**。深色底没问题，但底部互动栏在浅色模式下落在 `#f4f5f7` 面板上，
白底白图标自然几乎看不见——这正是你第三张截图的情况。

### 修复

新增一个统一的"未选中态颜色"裁决：

```java
static int idleActColor() {
    return MainActivity.DARK ? Color.WHITE : MainActivity.C_FG;
}
```

并按图标所在位置区分：

| 位置 | 背景 | 未选中色 |
|---|---|---|
| 横屏顶部栏 / 右侧竖排栏 | 压在视频画面上（可能很暗） | **保持白色**（保留阴影） |
| 底部互动栏（截图那一排） | 页面面板，浅色模式下是 `#f4f5f7` | **跟随 `C_FG`**（浅色模式 `#18191c`） |

`makeAct()` 增加 `onVideo` 参数，`Act` 记录 `idle` 颜色，`styleAct()` 改为：

```java
a.icon.setColorFilter(on ? onColor : a.idle);
```

所以：深色模式观感不变，浅色模式下图标自动变深，对比清晰。

## 三、评论点赞（主评论 + 楼中楼都能点）

### 新接口

`BiliApi.replyLike(aid, rpid, on)` → `POST https://api.bilibili.com/x/v2/reply/like`
参数 `oid=aid & type=1 & plat=1 & rpid=... & action=1|0 & csrf=...`，
失败直接抛异常交给调用方回滚。

### 交互设计

- 每条评论（含**二级回复**）的「时间」行新增一个**图标 + 数字**的点赞按钮，点击热区左右各扩大 10dp。
- **乐观更新**：点下瞬间就变主题色、数字 +1，不等网络。
- **失败回滚**：接口失败时自动还原颜色与数字，并 Toast 提示原因。
- **防连点**：同一条 rpid 正在请求时，重复点击直接忽略。
- **未登录拦截**：点之前先查登录态，未登录提示"请先登录 B 站账号"。
- **换视频自动清状态**：`likedReplies` / `likeDelta` / `likePending` 在切换视频时全部清空，不会把上一个视频的点赞状态带过来。

### 浅色模式配色

- 已点赞 → 主题强调色 `C_ACC`（品牌粉）
- 未点赞 → 深色模式 `#8A909C`、浅色模式 `C_SUB`（`#61666d`）

## 四、流畅度再优化

评论抽屉以前最大的卡顿源是 `Adapter.getView()`：**每次滚动都 new 一整套 View**
（头像 ImageView、两个 TextView、脚部 LinearLayout、点赞 TextView……），列表一滚就疯狂创建对象，
GC 一抖就是掉帧。本版做了四件事：

### 1. 行控件 ViewHolder 复用

- 固定子 View（头像 / 昵称 / 正文 / 时间 / 点赞 / 回复 / 楼中楼容器）只创建一次，之后只绑定数据。
- 监听器也只创建一次，通过 `Holder.row` 读当前评论，避免每次 `getView()` 都 new 一个 OnClickListener。

### 2. 稳定 id 用 rpid

`getItemId()` 从"返回位置"改成"返回评论 rpid"，ListView 才能正确判断该复用哪一行，
不再按位置错配（错配会导致头像和正文对不上）。

### 3. 楼中楼按需重建

新增 `threadStamp` 内容版本号，只在**数据真的变了**（展开 / 收起 / 拉到新回复 / 重新加载 / 切视频）时才重建那块 View。
普通滚动复用时直接跳过，省掉整块子 View 的构造。

### 4. 图标状态免重复设资源

`applyLike()` 里用 ImageView 的 tag 记住上一次的点赞状态，状态没变就跳过 `setImageResource()`，
少一次不必要的重绘。

> 配套：这些优化全部只改 `CommentSheet.java`（两版一致文件），平板 / 手机两版同步，
> 平板横屏分屏功能未受影响。

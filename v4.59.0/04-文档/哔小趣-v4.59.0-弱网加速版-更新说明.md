# 哔小趣 v4.59.0 弱网加速版 更新说明

版本：`4.59.0`（versionCode 160）
签名：与旧版一致（CN=Bixiaoqu），可直接覆盖安装，本地数据不丢
构建日期：2026-11-27

---

## 本版主题：全局线程调度 + 端口 + 直播加载窗口 + 弱网封面

四个诉求一次做完。核心是新增一个**全局网络质量档位**，让所有模块读同一份"网好不好"的判定，而不是各自拍脑袋定超时。

---

## 一、新增：NetQuality 弱网决策中心

此前每个模块各自定超时（封面 4s/8s、直播 API 15s/30s、取流 6s/9s），互不感知。弱网下要么一起超时把线程堵死，要么失败封面被反复重试。

现在收敛为一处：

- **探测**：进程内滑动窗口记录最近 12 次请求的成功率与耗时。
- **决策**：连续失败 / 高延迟 → 降档（短超时、小图、少并发、少预取）；连续成功 → 升档。
- **迟滞**：降档立即生效，升档要"失败率≤10% 且耗时<900ms"才逐级恢复，避免一次抖动就反复横跳。
- **网络类型**：移动网络起步即 FAIR（比 WiFi 保守一档）；切换 WiFi/移动时清空统计、重新判档。
- 纯 Java 逻辑，`NetQualityTest` JVM 单测 **15/15 全过**（降档、迟滞、恢复、策略值单调性）。

桥接层 `NetQualityAndroid` 单独放 Android 依赖（网络广播监听、定时同步），保持核心可单测。

### 各模块读取的策略值

| 档位 | 封面连接/读取超时 | 直播 API 超时 | 封面尺寸系数 | 并发上限 |
|---|---|---|---|---|
| 好网 GOOD | 4s / 8s | 10s / 15s | 1.0 | 8 |
| 一般 FAIR | 3.2s / 6.5s | 10s / 15s | 0.85 | 6 |
| 较差 POOR | 2.5s / 5s | 6s / 9s | 0.70 | 4 |
| 弱网 WEAK | 1.8s / 3.5s | 4s / 6s | 0.55 | 3 |

## 二、重点：弱网封面加载能力（ImgLoader）

1. **动态超时**：封面连接/读取超时随档位变化。好网保持原值不影响速度；弱网缩到 1.8s/3.5s，快速放弃换下一张，不再一张图堵住整条队列 8 秒。
2. **失败负缓存**：下载失败的 URL 记入负缓存（弱网 30s / 较差 15s / 好网 5s）。用户来回滑动时不再反复打到同一张必失败的图；成功即清除。
3. **弱网小图**：目标尺寸按档位缩小（弱网 0.55 倍，最低 96px），下载量大幅下降，先出图再谈清晰度。
4. **并发闸门**：信号量把真实并发收到档位上限（弱网 3 条），超出的排队或快速让位——避免十几条连接一起抢带宽、一起超时。
5. **弱网取消预取**：`prefetch()` 在较差/弱网档直接跳过。预取只为"下一屏秒开"，弱网下它只会和当前可见封面抢带宽，结果两张都慢；改为滑到时再取。所有调用点（首页/搜索/播放/动态）一次性生效。
6. **心跳上报**：每张封面的成功/耗时都喂给 NetQuality，网络变化即时反映。

---

## 三、直播加载窗口缓慢

1. **直播 API 短超时**：`liveAreas` / `liveRooms` / `livePlayUrls` 改用带超时的 `getJson()` 重载，读 NetQuality 档位。弱网下不再挂 15s/30s，快速失败 + 用缓存。
2. **房间列表缓存**：进程内 LruCache（key=分区+页，容量 12）。加载失败时先显示上次成功的列表并提示"网络较弱，显示上次内容"，窗口不再空白转圈。
3. **线程接入调度**：`loadZones` / `loadRooms` / `openPlayer` 的取址线程全部接入 `NetPrio(VIDEO)` 进程级优先级（此前 `loadZones`/`loadRooms` 是裸线程，调度器眼里和后台杂活平级）。
4. **心跳上报**：分区/房间/取流三处请求都喂给 NetQuality。

> 说明：本版**没有改动直播播放内核**（playUrl 接口、m3u8 转发、线路竞速保持 v4.54 版本），只优化加载链路，避免重蹈 v4.55 的覆辙。

---

## 四、端口优化

- **端口绑定重试**：`LiveProxy` 与 `LocalProxy` 的 `ServerSocket(0,...)` 绑定从 1 次改为最多 3 次（间隔递进 40/80ms）。偶发的端口 TIME_WAIT / 系统繁忙不再导致"直播代理启动失败"或点播入口不可用。
- 端口仍由系统分配（端口 0），避免固定端口冲突；绑定失败才抛异常。

---

## 五、冗余清理

- 删除 `LiveProxy` 中未使用的 `CopyOnWriteArrayList` import。
- 将 `NetQuality` 的 Android 依赖拆到 `NetQualityAndroid`，核心逻辑保持纯 Java 可单测。
- 统一 `BxqApp.VERSION`（遗留的 v4.47.1-exp → v4.59.0）。

## 七、建议实机验证

1. 弱网（可开流量并到地库/电梯，或开发者选项限速）下打开首页：封面应逐步出图、不再长时间转圈；来回滑动不重复请求同一张失败图。
2. 进入直播页：分区/房间列表应比旧版更快出内容；断网再进应显示上次缓存而非空白。
3. WiFi ↔ 流量切换：档位应重置，超时策略随之变化。
4. 反复退出/进入直播：不应再出现"直播代理启动失败"。

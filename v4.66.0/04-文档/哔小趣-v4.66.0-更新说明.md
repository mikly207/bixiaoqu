# 哔小趣 v4.66.0 · 旋转不重载版

基于 v4.65.0，本版修复**横竖屏切换时程序重新加载**的问题，并进一步优化加载速度。

---

## 一、修复：旋转不再重新加载

### 根因
Manifest 虽然声明了 `configChanges`，但 `MainActivity.onConfigurationChanged` 里旧逻辑是：

```
invalidateHomeCache()  →  清零数据缓存与滚动位置
recreate()             →  销毁并重建 Activity
```

重建会重新走 `onCreate` → `BiliApi.warmFinger()` + `switchTab(0)` → **`loadChannel()` 重新请求首页**、视频整批刷新、滚动位置丢失、界面闪一下。

### 修复方案
旋转/分屏改为**原地重排**，Activity 不重建、数据不重load：

| 步骤 | 说明 |
|---|---|
| 保存滚动位置 | 旋转前记下首页列表的滚动位置和偏移 |
| 原地重建列表 | 按新屏宽重新计算卡片宽度/列数（`FeedAdapter` 的尺寸是构造时算死的），但**复用现有 rows 数据**，绝不调用 `loadChannel()` |
| 恢复滚动位置 | 重排后列表停在原来的位置，不跳回顶部 |
| 底栏宽度重算 | 平板版横竖屏宽屏判定会变，同步更新底栏宽度 |
| 重抓液态玻璃 | 背景按新方向刷新 |

- **手机版**：列数固定双列、底栏参数固定，旋转几乎零成本，纯宽度自适应。
- **平板版**：列数按屏宽 2~4 列自适应，旋转只重建列表视图、不重新拉数据。

---

## 二、进一步优化加载速度

- **旋转后图片秒显**：`ImgLoader` 内存缓存 key 为图片 URL（与尺寸无关），旋转后同一批封面直接命中缓存，**零重新下载**，配合原地重排做到"转屏即到位"。
- **无重复网络请求**：旋转、切 tab、分屏拖动均复用已加载数据，不会触发重复的 `loadChannel` / 指纹预热。
- 保留 v4.64~v4.65 的全部优化：DNS 并行预热、弱网并发闸门、跟手底栏、渐变缓存等。
